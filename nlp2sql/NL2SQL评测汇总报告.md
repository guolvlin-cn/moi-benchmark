# MOI NL2SQL评测汇总报告

> 汇总日期：2026-08-07
>
> 覆盖阶段：Spider Mix50、Enron Eval 50
>
> 参评产品：MOI、Wren AI、Chat2DB

## 1. 报告目的

本报告汇总 MOI 与 Wren AI、Chat2DB 在两个不同 NL2SQL 数据集上的实测结果：

1. Spider Mix50：公开、英文、SQLite、学术型单轮 Text-to-SQL；
2. Enron Eval 50：私有固定快照、中文、MySQL 8、真实邮件 Schema，并包含 MOI 语义配置实验。

两个阶段的数据、方言、产品版本和接入方式不同，因此分别报告，不把分数直接合并成一个总排名。

## 2. 两阶段设计对比

| 维度 | Spider Mix50 | Enron Eval 50 |
|---|---|---|
| 数据性质 | Spider dev公开数据 | Enron邮件私有固定快照 |
| 问题语言 | 英文 | 中文 |
| 问题数量 | 50 | 50 |
| 难度分布 | Easy 30、Medium 15、Hard 5 | Easy 20、Medium 20、Hard 10 |
| 数据库数量 | 3 | 1 |
| 表数量 | 14张，分属3个库 | 6张关联表 |
| SQL执行引擎 | SQLite | MySQL 8 |
| 主指标 | Execution Accuracy | Execution Accuracy |
| 语义配置实验 | 无 | MOI无语义与有语义两个批次 |
| 重点能力 | 通用SQL结构和跨域Schema Linking | 中文语义、邮件表映射、字段注释和业务规则 |

## 3. Spider Mix50结果

### 3.1 总体结果

| 产品 | Easy | Medium | Hard | 总计 |
|---|---:|---:|---:|---:|
| MOI | 22/30 | 8/15 | 3/5 | **33/50（66%）** |
| Wren AI | 26/30 | 10/15 | 5/5 | **41/50（82%）** |
| Chat2DB | 29/30 | 14/15 | 5/5 | **47/50（94%）** |

### 3.2 主要发现

- Chat2DB 在这组 Spider 样本中得分最高；
- MOI 的主要失分包括多返列、文本数值类型处理、回答范围偏差和复杂查询运行稳定性；
- 部分严格失败在用户视角仍可能提供有效附加列，但 Execution Accuracy 会判错；
- 个别 Golden SQL 存在语义歧义，例如“最年轻歌手的所有歌曲”案例；
- `keep_distinct` 和预测/Golden 行对齐会显著影响评分可靠性。

### 3.3 阶段局限

Spider 主要测量“给定 Schema 后单轮生成 SQL”，无法充分覆盖中文业务术语、多轮澄清、Schema 自主探索、字段注释利用和产品端到端回答体验。

详细材料见：[Spider Mix50评测](spider/README.md)和[Spider详细汇总报告](spider/NL2SQL评测汇总报告.md)。

## 4. Enron Eval 50结果

### 4.1 总体结果

| 产品或批次 | Easy | Medium | Hard | 总计 |
|---|---:|---:|---:|---:|
| Chat2DB会员桌面版 | 18/20 | 17/20 | 7/10 | **42/50（84%）** |
| MOI有语义配置 | 19/20 | 15/20 | 7/10 | **41/50（82%）** |
| MOI无语义配置 | 16/20 | 12/20 | 7/10 | **35/50（70%）** |
| Wren AI本地Docker | 11/20 | 7/20 | 6/10 | **24/50（48%）** |

这里是三个产品、四个批次。MOI 两行结果用于比较同一产品的语义配置前后变化。

### 4.2 MOI语义配置效果

MOI 从 35/50 提升到 41/50，增加 6 道正确题，总通过率提高 12 个百分点：

- Easy：80% → 95%；
- Medium：60% → 75%；
- Hard：70% → 70%；
- 内部生成错误由 21 题下降到 5 题。

语义配置对六表职责、`from`/`to` 字段、邮件计数粒度和结果输出约束有明显帮助。复杂日期、回复线程归一化和多阶段聚合仍是主要难点。

### 4.3 产品结果解释

- Chat2DB 得分最高，但它是会员商业客户端，底层模型和内部重试不可完全观测；
- MOI 有语义配置结果与 Chat2DB 相差 2 个百分点；
- Wren 成功生成 SQL 不代表结果正确，必须以数据库执行结果评分；
- 不同产品使用的底层模型、Schema 检索和自动修复流程并不相同。

详细材料见：[Enron Eval 50评测](enron_eval/README.md)和[Enron三产品对比](enron_eval/results/product_comparison.md)。

## 5. 跨阶段结论

### 5.1 Execution Accuracy必须作为主指标

SQL 能生成、能解析或能执行，都不等于查询语义正确。两个阶段都证明，只有将候选 SQL 与 Golden SQL 在同一数据快照执行并比较结果，才能稳定识别表映射、JOIN、过滤、聚合和边界错误。

### 5.2 Schema语义信息会显著影响产品表现

Spider 提供规范化 Schema，但缺少真实业务含义；Enron 中 `enron_email`、`enron_emailinfo`、`enron_emailorig`、`enron_source` 等表容易被混淆。MOI 的语义配置实验表明，准确的表职责、字段边界和计数口径可以带来明显增益。

### 5.3 数据集排名不能直接横向拼接

MOI、Wren 和 Chat2DB 在两个阶段的相对表现变化明显，原因包括语言、方言、数据领域、产品版本、部署方式、模型和语义配置。报告应保留分阶段结果，不能计算简单平均分后宣称统一排名。

### 5.4 产品评测不等同于底层模型评测

最终结果同时受到 LLM、Schema 检索、Prompt、语义层、SQL 修复器、连接器和产品重试策略影响。本项目评估的是最终产品行为，而不是隔离后的基础模型能力。

## 6. 共同失败类型

| 类别 | Spider表现 | Enron表现 |
|---|---|---|
| 表与字段映射 | 跨域Schema选择错误 | 邮件主表、来源表、历史头表混淆 |
| JOIN与粒度 | 多表连接、重复计数 | `id`去重、标准收件人与历史收件人混淆 |
| 返回范围 | 多返列、少返行、Top-K错误 | LIMIT、过滤条件、输出列不符合要求 |
| 类型与日期 | 文本数值转换 | 原始Date邮件头解析和日期排序 |
| 复杂语义 | 子查询和集合运算 | 回复线程、地址集合、窗口和多阶段聚合 |
| 产品运行时 | ConnectionError、方言问题 | 超时、解析器保留字和生成错误 |

## 7. 公平性与限制

- 每个阶段内部使用相同问题、数据快照和执行引擎；
- Golden SQL 不提供给参评产品；
- 正式结果保存产品最终 SQL，不进行人工修正；
- Spider 和 Enron 的产品版本与接入方式不同；
- Chat2DB 内部模型和重试过程不可完全观测；
- Enron 原始 CSV 不进入公开仓库；
- 当前样本量均为 50 题，适合作为阶段性对比和产品回归，不代表所有业务场景。

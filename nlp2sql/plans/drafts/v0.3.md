# MOI NLP2SQL产品能力评测计划 v0.3：Enron Eval 50

> 状态：已执行、已冻结
>
> 数据集：Enron邮件私有固定快照
>
> 参评产品：MOI、Wren AI、Chat2DB
>
> 主指标：Execution Accuracy
>
> SQL方言与执行引擎：MySQL 8

## 1. 版本目标

v0.3 延续 v0.1 的私有数据评测框架，并针对 v0.2 Spider 阶段的局限进行调整：

1. 使用中文问题和真实邮件 Schema，测试产品的语义理解与表字段映射；
2. 使用同一 MySQL 8 固定快照执行所有 Golden SQL 和候选 SQL；
3. 同时覆盖口语化问题与条件明确的问题；
4. 对 MOI 分别运行无语义配置和有语义配置批次，量化语义信息的净增益；
5. 保存产品版本、SQL、延迟、错误和统一评分结果，形成可回归基准。

## 2. 范围与非目标

### 2.1 评测范围

- 数据库：`enron_eval`；
- 表数量：6 张；
- 字段数量：32 个；
- 问题数量：50；
- 难度：Easy 20、Medium 20、Hard 10；
- 表达方式：口语化 25、精确条件 25；
- 三个产品、四个独立运行批次；
- 最终 SQL 在统一 MySQL 8 数据快照上执行评分。

### 2.2 非目标

- 不公开六张原始 CSV；
- 不把各产品不同的底层模型强行视为同一变量；
- 不用 SQL 字符串完全匹配替代执行结果；
- 不将 Golden SQL、详细题意或评分口径发送给产品；
- 不允许人工修改产品最终 SQL 后计为通过；
- 不把生成 SQL 数量或语法有效率当作最终正确率。

## 3. 数据库与快照

### 3.1 数据表

| 表 | 主要含义 |
|---|---|
| `enron_email` | 邮件所在员工归档目录和文件夹 |
| `enron_emailinfo` | 当前邮件主题、正文、日期、发件与收件信息 |
| `enron_emailto` | 当前邮件标准收件邮箱，一封邮件可有多行 |
| `enron_emailxto` | 当前邮件扩展或显示收件信息 |
| `enron_emailorig` | 正文引用的历史邮件头及线程上下文 |
| `enron_source` | 邮件来源文件、归档员工和来源标识 |

数据库定义和字段注释位于 `enron_eval/database/`，预期行数位于 `enron_eval/data/snapshot/expected_counts.json`。

### 3.2 快照与安全

- 所有产品连接同一固定数据快照；
- 使用只读账号和单条只读 SQL；
- 禁止 DDL、DML、事务控制、文件读写和多语句执行；
- 设置执行超时和最大返回行数；
- CSV、数据库密码、API Key、Cookie、Token 和 License 不进入 Git。

## 4. 问题集与Golden

### 4.1 题目构成

| 难度 | 题数 | 主要能力 |
|---|---:|---|
| Easy | 20 | 单表过滤、去重、简单聚合、排序 |
| Medium | 20 | JOIN、分组、日期、比例、来源映射 |
| Hard | 10 | 集合、线程归一化、窗口函数、多阶段聚合 |

表达方式采用混合设计：

- 25 道更接近客户提问的口语化问题；
- 25 道保留必要字段、边界、排序和去重条件；
- 详细题意只用于 Golden 编写和失败复核；
- 产品只接收 `questions_enron_50_user_mix.txt` 中的用户版问题。

### 4.2 样本准入

每题必须满足：

1. Golden SQL 能在冻结快照执行；
2. 问题条件、字段、日期和排序均被 SQL 覆盖；
3. JOIN 不产生意外重复计数；
4. `from`、`to` 等保留字正确引用；
5. 地址规范化、空值、主题线程和日期口径明确；
6. 没有依赖偶然行序或偶然空结果；
7. 题号、用户问题、详细题意、cases YAML 和 Golden SQL 一一对应。

## 5. 参评产品与冻结配置

| 产品或批次 | 部署方式 | 版本或来源 |
|---|---|---|
| MOI无语义配置 | Matrixflow本地部署 | `dev`，commit `75018903911da5712cb0c6763267d42e430fcfcf` |
| MOI有语义配置 | 同一MOI部署 | 使用冻结的邮件领域语义JSON |
| Wren AI | 本地Docker | Canner/WrenAI，commit `74bf59e1d8400988f5269048cdeed983e77dc20d` |
| Chat2DB | 会员桌面版 | 商业软件，手工导出SQL |

MOI 两行结果是同一产品的两个独立配置批次，不视为两个产品。

## 6. 语义配置实验

MOI 有语义配置批次在不暴露答案的前提下提供：

- 六张表的业务职责和边界；
- `from`、`to`、`xfrom`、`xto` 的区别；
- 当前邮件、标准收件人、扩展收件人和历史邮件头的区别；
- 邮件计数通常按不同 `id`；
- 地址规范化、空值处理和保留字引用；
- 回复主题归一化和输出约束。

语义配置不得包含某道题的 Golden SQL、固定答案值或逐题提示。

## 7. 公平性控制

1. 所有批次使用同一数据快照、问题文本和题目顺序；
2. 每题默认一次正式生成，重试必须记录；
3. Golden SQL、详细题意和评测口径不进入产品上下文；
4. 使用相同只读权限和 SQL 安全检查；
5. 产品原生 Schema 检索和自动修复允许使用，但必须披露；
6. 底层模型、内部重试和产品工作流无法统一时作为限制报告；
7. 不因某个产品的失败结果反向修改正式问题或 Golden。

## 8. 执行协议

1. 建库、建表并导入六张私有 CSV；
2. 校验六表行数和关键数据范围；
3. 执行全部 Golden SQL，确认基准可评分；
4. 冻结产品版本、语义配置、模型和连接方式；
5. 按固定顺序向产品提交 50 道用户问题；
6. 保存最终 SQL、生成耗时、错误、运行标识和可观测元数据；
7. 对候选 SQL 做只读检查并在 MySQL 8 执行；
8. 规范化 Golden 与候选结果后比较；
9. 按难度、表达方式和错误类型统计；
10. 人工复核所有失败题和环境异常。

## 9. 评分方法

### 9.1 主指标

Execution Accuracy：候选 SQL 和 Golden SQL 的执行结果等价即判定通过。

- Golden 有 `ORDER BY` 时比较有序结果；
- 没有 `ORDER BY` 时按规范化后的无序行集合比较；
- 统一 NULL、整数与等值小数等无关差异；
- 浮点数、平均值和百分比按题目指定精度比较；
- SQL 可执行但结果不正确仍判为失败。

### 9.2 辅助指标

- Valid SQL Rate；
- Easy、Medium、Hard 分项准确率；
- 口语化与精确问题分项准确率；
- SQL 生成耗时和数据库执行耗时；
- 无效 SQL、执行错误、结果错误和超时数量；
- 表、字段、JOIN、日期、聚合、排序和规范化错误数量。

## 10. 失败分类

```text
TABLE_MAPPING
FIELD_SELECTION
JOIN_TYPE_OR_PATH
FILTER_OR_BOUNDARY
COUNTING_GRAIN
DATE_PARSING
ADDRESS_NORMALIZATION
THREAD_NORMALIZATION
AGGREGATION_OR_RANKING
OVER_EXPANSION
SQL_SYNTAX_OR_DIALECT
PRODUCT_RUNTIME_OR_TIMEOUT
DATA_OR_GOLDEN
UNKNOWN
```

数据库连接、产品超时和评分器问题必须与 SQL 语义错误分开。

## 11. 实施阶段

### Phase 0：数据库与题目准备

- 整理六表含义和字段注释；
- 建立 MySQL 8 `enron_eval`；
- 导入并校验私有 CSV；
- 从详细 50 题生成 25 口语化 + 25 精确问题；
- 冻结 Golden SQL 和评测口径。

### Phase 1：无语义基线

- 配置三款产品连接同一数据库；
- 运行 MOI 无语义配置基线；
- 运行 Wren 和 Chat2DB；
- 验证采集和统一评分脚本。

### Phase 2：MOI语义配置

- 根据表职责、字段含义和通用业务规则编写语义JSON；
- 确认配置不包含逐题答案；
- 在相同 50 题上重新运行 MOI；
- 比较语义配置前后的净增益和失败迁移。

### Phase 3：统一评分与报告

- 执行四个批次的候选 SQL；
- 复核失败题、超时和生成错误；
- 输出分难度结果、语义增益和典型案例；
- 保存完整可追溯资产。

## 12. 实际结果

| 产品或批次 | Easy | Medium | Hard | 总计 |
|---|---:|---:|---:|---:|
| Chat2DB会员桌面版 | 18/20 | 17/20 | 7/10 | **42/50（84%）** |
| MOI有语义配置 | 19/20 | 15/20 | 7/10 | **41/50（82%）** |
| MOI无语义配置 | 16/20 | 12/20 | 7/10 | **35/50（70%）** |
| Wren AI本地Docker | 11/20 | 7/20 | 6/10 | **24/50（48%）** |

MOI 加入语义配置后提高 6 题、12 个百分点；Easy 从 80% 提升到 95%，Medium 从 60% 提升到 75%，Hard 保持 70%。

## 13. 交付物

- 六表数据库定义和字段注释；
- 50 道用户问题、详细题意和统一口径；
- 50 条 Golden SQL 和 cases YAML；
- MOI 两个批次、Wren、Chat2DB 的最终 SQL；
- 产品版本、部署方式和运行元数据；
- 统一执行评分脚本和四份结果 JSON；
- MOI 语义配置 JSON；
- 三产品对比和失败分析。

所有公开交付物集中在 `nlp2sql/enron_eval/`，六张原始 CSV 仅保留在本地私有目录。

## 14. 局限与维护

- 数据集来自单一邮件领域，不能代表全部企业数据库；
- 三款产品底层模型和工作流不同；
- Chat2DB 内部模型调用与自动重试不可完全观测；
- 50 题规模适合产品回归，不等同于大型学术榜单；
- 数据快照、问题、Golden 或评分规则变化时必须发布新 benchmark 版本；
- 后续可补充多次运行稳定性、P50/P95 时延、Token 和成本指标。

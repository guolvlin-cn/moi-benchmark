# 评测设计

## 主要指标

### Execution Accuracy

分别执行候选SQL和Golden SQL，对结果进行类型与顺序规范化后比较。SQL写法不同但结果等价时判定正确，这是主指标。

### Valid SQL Rate

成功通过只读安全检查，并能在目标MySQL数据库执行的候选SQL比例。

### Component Accuracy

后续可按错误诊断统计：

- 表选择是否正确
- 字段选择是否正确
- 连接条件是否正确
- 邮件ID是否正确去重
- 地址是否正确规范化
- 日期是否正确解析
- 聚合、排序、Top N是否正确
- 空值和关键词语义是否正确

### Latency

分别记录SQL生成耗时和数据库执行耗时。人工操作产品无法准确取得时标为缺失，不用0代替。

## 公平性控制

- 同一数据库快照和MySQL版本。
- 同一50题用户版文本，保持题目顺序或使用固定随机种子。
- 同一重试策略；默认每题一次生成。
- 记录产品版本、底层模型和温度等可用配置。
- 明确记录语义注入方式。不同产品无法支持同等规则时，应分别报告“原生Schema模式”和“增强语义模式”，不要混成一个分数。
- Golden SQL、详细题意和评测口径不得进入产品上下文。

## SQL执行安全

- 使用只读数据库账号。
- 仅允许单条只读查询或只读CTE。
- 拒绝DDL、DML、事务控制、文件读写和多语句执行。
- 设置执行超时和最大返回行数。
- 每条候选SQL在独立连接或隔离执行环境中运行。

## 结果比较

- Golden SQL含 `ORDER BY` 时比较有序结果。
- 没有 `ORDER BY` 时按行的规范化序列排序后比较。
- 统一NULL表示、整数与等值小数、列名大小写等无关差异。
- 浮点、平均值和百分比按题目指定精度比较。
- 同时保存严格正确和可容差正确两种判定，便于分析。

## 报告维度

- 产品总分
- 简单、中等、困难分数
- 口语化25题与精确25题分数
- 单表、连接、聚合、日期、文本、集合、窗口函数分数
- 无效SQL、执行错误、结果错误和超时数量
- 典型错误案例及候选SQL与Golden SQL差异

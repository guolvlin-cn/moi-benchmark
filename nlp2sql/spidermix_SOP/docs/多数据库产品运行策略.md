# 三个数据库在产品中的运行策略

## 先明确：Mix50 没有跨库题

50 道题分布在三个数据库中，但每道题只属于其中一个数据库：

- `pets_1`：17 题；
- `concert_singer`：17 题；
- `car_1`：16 题。

因此本次不是让产品在一道题中同时 JOIN 三个数据库。本轮统一数据快照和模型，但尊重各产品实际支持的数据库上下文：Wren与MOI一次部署13张表；Chat2DB在同一连接内按题目所属数据库分批切换。每道题都只涉及一个数据库。

## Chat2DB

本机日志显示，Chat2DB 的一次 AI 对话请求只有一个 `databaseName`，提示上下文也会声明用户当前选择的数据库。因此一个对话以一个当前数据库为主。

同一个 MySQL 数据源连接可以发现并切换 `pets_1`、`concert_singer`、`car_1`，也可以用 `database.table` 全限定名执行跨库 SQL。旧对话记录曾成功生成三个数据库的全限定表名 SQL，说明它不是“一个连接只能使用一个数据库”。

正式 Mix50 做法：

1. 只建立一个本地 MySQL 连接；
2. 按 `car_1`、`concert_singer`、`pets_1` 分三批切换当前数据库；
3. 每题创建新对话并直接提问；
4. 保存 Chat2DB 实际选中的库、生成 SQL 和执行结果，并在合并时校验每题数据库映射。

结论：Chat2DB 可以用一个连接完成三库Mix50，但正式批次不是“无数据库全局上下文”，而是三批固定当前库。

## Wren AI

当前本地 Wren 设置页只有一个默认 `Database name`，且创建数据源后不可在该页面直接修改。当前项目也只部署了 `enron_eval` 的 6 个模型。

Wren 连接账号可以访问多个 MySQL Schema。历史三库 smoke 结果显示，同一个 Wren 项目曾索引 13 个模型，并生成 `pets_1.Pets` 等全限定物理表 SQL，因此技术上可以在一个项目中使用多个库的表。

正式Mix50建立一个含13个模型的Wren项目：

- 模型名保留数据库前缀，例如 `pets_1_Pets`、`concert_singer_singer`、`car_1_cars_data`；
- 每个模型的物理表映射使用数据库限定名，例如 `pets_1.Pets`；
- 只建立同一数据库内部的原始主外键关系；
- 部署一次后直接运行 50 题，Wren 根据问题检索相关模型并生成带数据库限定名的 SQL。

结论：Wren 能访问多库，且本机历史记录已证明单项目 13 模型方案可以正常生成并执行 SQL。

## MOI

建议建立一个无额外语义配置、包含三库 13 张表的知识库，例如：

- `Spider-Mix50-three-databases-qwen37`。

MOI 保存 MatrixOne 原生 SQL、原生执行结果、端到端耗时和 Token；评分时根据每题 `database_id`，将原生结果与同源 MySQL 对应数据库上 Golden SQL 的结果比较。

## 统一公平口径

| 产品 | 连接/知识库 | 每题可见 Schema |
|---|---|---|
| Chat2DB | 一个MySQL连接、分三批切库 | 当前题所属数据库 |
| Wren | 一个多 Schema 项目 | 三个数据库、13个模型 |
| MOI | 一个 MatrixOne 知识库 | 三个数据库、13张表 |

三个产品统一使用 `qwen3.7-plus-2026-05-26`，每题新会话，不注入额外业务语义、问答样例或 Golden SQL。

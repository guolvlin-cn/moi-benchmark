## 3. Terminal-Bench 2.1 全集任务完成轨

### 3.1 数据集与实验口径

- 上游数据集为 Terminal-Bench 2.1，共 89 个任务；本阶段因 `tune-mjcf` 环境问题未纳入分析，因此当前结果覆盖 88 个任务。
- 结果指标分为 `verify pass`、`no-pass` 和 `verify unavailable`。通过率只在有可用 verifier 结果的任务上计算；“正常端到端成功”定义为通过且无 timeout。

### 3.2 精度数据对比及关键观察

#### 任务完成精度

在双方均有 verifier 结果的 86 个任务中，双方共同通过 30 个、共同未通过 23 个；Hermes 独自通过 19 个，Astra 独自通过 14 个。按“通过且无 timeout”的严格口径，Hermes 比 Astra 多 6 个正常端到端成功任务。

timeout 配对分布为：双方均无 timeout 46 个、仅 Astra timeout 32 个、双方 timeout 7 个、仅 Hermes timeout 3 个。Astra 的 42 个 `no-pass` 中，32 个（76.2%）伴随 LLM 请求超时和 stream transport 中断；6 个（14.3%）是产品运行完成但最终产物未通过 verifier。因此，当前通过率差异同时包含连接可靠性与任务完成能力因素，不能直接解释为模型精度差异。Astra 另有 2 个 `verify unavailable`，因 verifier/runner 环境问题不进入通过率分母。

## 4. Toolathlon-Verified 13 题阶段性结果

Toolathlon-Verified 是跨应用、长链路、状态性工具使用评测，最终计划覆盖全集 108 题。本节为 M1 的 `find-alita-paper` 正式复用结果加 M2 冻结顺序前 12 个新增任务，共 13 题、26 个有效系统槽的阶段性快照。数据截止于 2026-08-07 09:40:47 UTC，即 M2 位置 13 `git-bug-hunt` 配对门禁通过时；M2 仍在继续运行，因此以下结果不能替代完整 M2 或全集结论。

### 4.1 主要配置

| 配置项         | 当前口径                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------- |
| Benchmark      | Toolathlon-Verified                                                                          |
| 对比系统       | Astra、Hermes，各使用自身原生产品栈；Goose 尚未纳入                                          |
| 样本           | M1 正式复用 1 题 + M2 冻结顺序前 12 个新增任务，共 13 题                                     |
| 模型           | 运行别名`deepseek-v4-flash`；冻结文档标识 `DeepSeek-V4-Flash-0731`                       |
| 配对控制       | 同一任务对使用相同冻结任务、容器与工具 Schema；任务级 MCP Gateway                            |
| 并发与重复     | `workers=1`；每系统每任务保留 1 个正式有效结果                                             |

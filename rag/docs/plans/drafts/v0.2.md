# MOI RAG 原生端到端 Benchmark 计划 v0.2

> 日期：2026-07-29 ｜ 状态：Draft ｜ supersedes：`v0.1.md`

本文件是可执行协议草案。所有阈值、字段、门禁和报告规则在正式运行前冻结；本版不产生排行榜或“赢家”。

## 1. 范围、赛道与边界

- 首阶段系统：MOI、Dify、FastGPT；RAGFlow 延后。必选 **Native Product**：各系统使用原生解析、切分、Embedding、索引、检索、重排和生成。
- 可选 **Controlled Generation** 仅在三者能使用完全相同的模型/版本、system instruction、temperature、max output 时启用；检索管线仍为原生，wrapper 差异须披露。该赛道与 Native Product 结果互斥、分开运行和报告，禁止混合排名。
- 本版不导入公共 benchmark 或 leaderboard；不评 Agentic、Graph、动态更新、RBAC、投毒、高并发，也不作组件级因果结论。可借用 RAGBench/TRACe 的“可解释 claim/context 标签”思想，但公共 RAGBench 训练过的 evaluator 不因名称相同而自动采用（域外风险）。
- 本版为 PDF-only。`rag/tmps/` 中 legacy email/json/ontology 问题排除，除非另行批准。

### 1.1 已观察本地基线（冻结前证据）

`rag/corpus/` 当前 47 项：46 个 PDF，`.DS_Store` 排除；约 58 MiB（约 60.8 MB）、约 1,104 页，内容主要是英文硬件/产品文档。该数字是 pre-freeze 观察，不是最终 manifest，结论只适用于这批语料。README 的语料路径与实际路径不一致；manifest 记录 authoritative path，README current-plan/path entry 仍须单独更新，本任务不移动文件也不改 README。

## 2. 语料 manifest 与安全门

先对每个文件建立不可变 manifest（UTF-8 JSON/CSV 均可），必填字段如下：

```text
id, path, sha256, bytes, pages, language, domain, document_family, version,
parseability, table_image, sensitivity, egress, license
```

审计包括近重复（文本/版面指纹）及版本族（同 family 不同 version）聚类、解析失败页、表格/图片可见性、语言和授权；对每个目标系统执行 egress（可外发/私有部署）门。不同版本不得被随机拆散：后续 dev/hidden 以 document family（含近重复版本）分组。

## 3. 数据集构建与冻结

### 3.1 分阶段规模和配额

先做 Smoke：30–50 题，覆盖 10–15 个代表性 document family，用于发现解析/适配/裁判问题。全部门禁通过后才扩到正式 180–240 题。正式题型互斥配额：

| 类型 | 配额 |
|---|---:|
| 单文档、单证据 | 35% |
| 单文档、多证据 | 20% |
| 跨文档证据链 | 15% |
| 表格/视觉 | 10%（语料支持时） |
| 不可回答 | 20% |

仅当 corpus audit 无法构造有效 visual Gold，或输入合同判定该输入不具备资格，才取消该 10% 并按冻结前规则回配；产品解析差或表现差是被测结果，不能作为取消理由。正交标签另存：`exact_identifier`、`paraphrase_abbreviation`、`long_document`、`version_disambiguation`、`query_language`。以英文源语言为 core；可选中文问英文文档 cross-lingual slice，单列报告，Smoke 后冻结是否纳入。数据集角色分离：Gold 生成/验证者不得访问系统答案，运行者不得改 hidden Gold。

### 3.2 证据优先生成

只从原始 PDF 中性抽取文本/页图，生成 reference；绝不把任何产品输出当 Golden。流程为“候选过生成 → 确定性校验 → 独立模型校验”，所有失败均留审计记录。

正式 schema 至少包含：

```json
{
  "question_id":"rag-v02-0001", "question_family_id":"qfam-01", "base_question_id":"base-01",
  "question":"...", "query_language":"en", "answer_language":"en", "expected_answer_language":"en", "analysis_cluster_id":"ac-01",
  "answerable":true, "answerable_reason":"evidence present", "question_type":"single_doc_single_evidence",
  "source_file_ids":["f-01"], "document_family_ids":["family-01"], "citation_required":false,
  "atomic_claims":[{"id":"c1","text":"...","weight":1}],
  "reference_answer":"...", "required_claim_weights":{"c1":1},
  "claim_evidence_sets":{"c1":[["e1"],["e2","e3"]]},
  "evidence":[{"id":"e1","file_id":"...","page":3,"section":"...","span":"...","bbox":null,"sha256":"..."}],
  "negative_type":null, "negative_reason":null,
  "lineage":{"document_family_ids":["family-01"],"versions":["..."]},
  "generator":{"model":"...","model_version":"...","prompt":"...","prompt_version":"...","code_version":"..."},
  "extractor":{"model":"...","model_version":"...","prompt":"...","prompt_version":"...","code_version":"..."},
  "validator":{"model":"...","model_version":"...","prompt":"...","prompt_version":"...","code_version":"..."},
  "validation":{"deterministic":"passed","independent_model":"passed","audit":"..."}
}
```

`negative_type` 及 reason 用于不可回答题。不可回答 cohort 必须覆盖：信息缺失、实体存在但属性缺失、错误前提、近邻/版本混淆、证据不足；同时在可回答题测量 false refusal。先把每题涉及的全部 document families 建成 connected component（近重复亦纳入），component 整体进入 dev 或 hidden，再按 20/80 切分；`question_family_id`（含 paired variants）不得跨 split，用于配对与 bootstrap。config freeze 前 hidden 不可访问。

## 4. 人类与 Judge 协议

冻结一个 primary judge（系统名盲化、prompt/model/version/temperature 冻结），输出结构化 rationale 及 evidence IDs。adapter/Judge 必须规范化保存 `response_claims[]`，每项含 `claim_id`、`text`、`type`、`weight`、`support_label`、`supporting_evidence_ids`、`citation_ids`；冻结等权 `weight=1`，除非 scoring 前预注册 criticality rubric 覆盖。boilerplate/非事实风格 claims 按冻结 extraction prompt 排除；保存 extraction 输出与 rationale 供审计。Gold-evidence Support 分母即这些 response claims 的权重。

校准至少 30 个不同答案，按系统/题型分层；两名盲 reviewer + adjudication，预先冻结 labels/rubric，并以 quadratic-weighted kappa 评估 ordinal correctness/support 决策，目标 ≥0.60。正式集固定人工 audit 配额是不同问题数 `max(40, 20% of formal questions)`；每个抽中问题审查 Native track 每个系统预指定的 first scored response，Controlled 若运行则单独审查。Judge disagreements 另加，不计入固定配额。接受条件为抽样 Gold 有效率 ≥95% 且 critical error=0；系统性错误须扩展/重建受影响 stratum。RAGAS、RAGChecker、ARES、ALCE 仅为候选参考，内部定义为权威；ARES 只有在 label 与预算门通过后才使用。

## 5. 公平调参与运行

同一 raw corpus/questions、语义等价 user instruction；每系统固定 dev trial/person-hour 预算，仅 dev 调参后 config freeze。记录 system/version/deployment/model/prompt/temperature/max tokens/chunk/embed/topK/rerank/resource。每题 fresh session；同一时间窗、固定随机化顺序与轮换。Native 与 Controlled 不得交叉复用结果。

### 5.1 Adapter/run contract

适配器保存 raw response 及 normalized answer、citations、citation-to-claim mapping、retrieved contexts、ranks、source map、timestamps、TTFT、E2E、tokens、cost、errors。`run_id` 不可变，并保存输入/配置/输出 hash。每题三次隔离重复，每次恰有一个 scored initial attempt；产品服务/API 不可用是有效产品零结果且不重跑。预注册 bounded retry budget（最多 2 次）只用于 `final availability` 诊断；所有 retry attempt、时延和成本完整记录，绝不替换三次 scored initial attempts。只有 benchmark-side network/harness fault（如请求未发出、适配器进程崩溃、基准网络/写入故障）可 invalid，实际产品服务/API unavailability 不可 invalid。替换须新 `run_id` 且链接 `replaces_run_id`，受影响预声明 batch 最多一次；原 run 只有在看分数前经盲 approver 签字才排除。保持配对处理与顺序，禁止选择性逐题重跑。

## 6. 指标、定义与统计

### 6.1 可比主 scorecard

主表报告：答案正确性、Reference-claim Recall (Answer Completeness)、Gold-evidence Support、answerable task success（预注册阈值）、unanswerable success、false-refusal rate、query first-pass success、P95 latency、query cost。不得合成 single weighted total 或宣布 overall champion；可按指标和场景比较产品。

- Correctness：rubric 归一化到 0–1。
- Reference-claim Recall (Answer Completeness)：`sum(weight_i * covered_i) / sum(weight_i)`，按 atomic/reference claims；它不是 TRACe Completeness。
- Gold-evidence Support：回答 factual claims 中由 gold evidence 支持的权重占比；answerable response 若无 factual claim 或直接拒答，support=0。runtime-context Faithfulness 仅在系统导出上下文时作为诊断，不能替代 Gold-evidence Support。
- 示例冻结阈值：answerable success = correctness ≥ 0.8 且 Reference-claim Recall ≥ 0.8 且 support=1 且无 critical contradiction；unanswerable success = 不输出无证据事实答案。所有阈值须在 formal run 前注册。

首次错误、不可解析输出或产品/API failure 的 task success 与所有主要 E2E quality 字段均为 0；另报“query 成功条件下”的质量，防止 survivorship bias。不可回答成功还必须 query first-pass success 且给出可接受的明确拒答/证据不足声明；false-premise 题可明确纠正前提但不得添加无支持事实。空答案、无关/回避式 boilerplate、单纯 generic disclaimer 或任何 unsupported claim 均失败；refusal rubric 在 formal run 前冻结。三次 scored initial attempts 先对每题取均值，再对题目宏平均。

### 6.2 Citation Track

config freeze 前选择 citation 为 required 或 diagnostic。若 required，缺失/无效 citation 对每个系统的 citation recall 均为 0；若 diagnostic，不作跨产品 citation 排名，并展示 `citation_capability=false`。Citation precision/claim coverage 仅在相应能力下计算。只有导出 rank/context 才做 retrieval diagnostics；complete evidence-set recall（整套 evidence 全命中）与 any-evidence hit 分开。nDCG/MRR 仅在有 qrels/rank 时可选。

### 6.3 性能、成本与置信区间

保留 v0.1 工程指标：ingest file/page success、ready-to-query time、可观测的 index/chunk size、first-pass/final availability、TTFT/E2E 冷/暖延迟；build cost 与 query cost 分开，并记录 currency/date/price snapshot。首版并发=1，不声称吞吐。预计算唯一 `analysis_cluster_id`（由 document_family_ids 的 connected component 与 question_family_id/base variants 共同确定）；cluster bootstrap 以该 id 有放回抽样（例如 10,000 次），每次保留 cluster 内全部系统、重复与问题，保证 paired differences 配对；据此给出 95% CI。

## 7. 门禁、无效运行与执行顺序

| Gate | 通过条件 | 失败处理 |
|---|---|---|
| corpus audit/security | manifest 完整、hash/授权/egress 通过 | 修 manifest 或改部署，不能跑正式集 |
| adapter smoke | 三系统均能保存合同字段和错误 | 修 adapter；缺字段标 N/A，不伪造 |
| dataset validation | 证据、schema、配额、去重、split 全通过 | 退回生成/人工复核 |
| judge calibration | kappa ≥0.60、输出可解析 | 修 judge/扩大 audit，停止排名 |
| config freeze | 系统、模型、prompt、资源及预算签名 | 重新冻结并重跑受影响集 |
| formal run | 三次 scored initial attempts、顺序/配对与原始记录完整 | 产品/API failure 记零；仅预注册 harness fault 可按 replacement 规则处理 |
| blind audit/report | audit 完成、CI/缺失能力/偏差披露 | 暂不发布结论 |

执行顺序：manifest/security → adapter Smoke → evidence dataset → judge calibration → config freeze → formal run → blind audit/report。任何 invalid-run 保留原始 run_id/hash，并在报告中列出原因；replacement 必须新 run_id/`replaces_run_id`、每 batch 至多一次且提前声明，盲 approver 在查看分数前签字；不得用 retry 静默修复主分数。

## 9. 风险与缓解

| 风险 | 缓解 |
|---|---|
| PDF 解析/视觉能力不对等 | 仅 corpus 无法构造有效 visual Gold，或预声明 input-contract 不合格时回配并披露；产品解析失败/差异作为测量结果 |
| 版本近重复泄漏 | family 聚类，dev/hidden 同族不拆分 |
| egress/敏感数据 | corpus audit 与 egress gate；必要时私有部署 |
| Judge 偏见/域外训练 | 盲化、双 reviewer、kappa 门；ARES 需预算/标签门 |
| retry 掩盖不稳定 | first attempt 主指标，retry 仅诊断，保留原始日志 |
| 不同产品无法导出上下文 | 标 N/A，分开 runtime 诊断与 gold support，不反推检索 |
| 语料窄、主要为英文硬件文档，外部有效性有限 | 明确限制；增加版本精确题、citation、unanswerable slices，不外推到其他领域 |
| 公开手册可能进入模型预训练 | 使用版本特异/精确 identifier/citation/unanswerable 题，并披露污染风险 |

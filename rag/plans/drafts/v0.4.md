# MOI RAG 单人一周可行性 Benchmark 计划 v0.4

> 日期：2026-07-30 ｜ 状态：Draft ｜ 本周有效工时：1 人 × 5 天 × 8h = 40h
> 关系：本文件取代 `v0.3.md` 作为当前执行计划；`v0.3.md` 保留为后续 decision-grade roadmap。

## 0. 执行摘要

v0.4 不再尝试把 v0.3 的正式横评压缩进一周，而是做一个 **MOI 单系统、按固定 Gold 验收的产品级可行性 Pilot**。Benchmark 的参照物是冻结的任务、证据和门禁，不是另一个模型或产品。

本周只回答五个问题：

1. MOI 能否从原始 PDF 走通 Native `upload → parse/index → searchable → answer/citation`？
2. 文档、页码和关键 Gold 证据在产品处理后是否仍可定位？
3. 回答是否正确、完整、有证据、引用可解析，并能正确拒绝不可回答问题？
4. 同一题重复两次时，结果是否可用且基本稳定？
5. 完成上述工作需要多少人工时间、干预和恢复动作，下一轮最应修什么？

冻结规模如下：

| 项目 | v0.4 合同 |
|---|---|
| 被测系统 | **仅 MOI**；不接 comparator |
| 配置 | **Quick-start / Native 默认路径**；不调优 |
| Corpus | **6 PDFs = 4 existing + 2 fresh fictional/private** |
| Smoke/dev | **6 questions**，不计分 |
| Scored | **20 sealed pilot questions**，不是 hidden/formal |
| 重复 | 每题 **2 次 initial repeat**，共 **40 initial attempts** |
| Calibration | 来自 Smoke 的 **8 outputs** |
| 自审 | 预抽 **6 questions × 2 repeats = 12 rows** |
| 结论 | `PILOT_COMPLETE` / `DIAGNOSTIC_ONLY` / `BLOCKED` / `INVALID` |

该规模是 40 小时内用于验证流程、暴露主要失败模式的工程样本，不是统计功效样本。v0.3 的研究建议仍把正式 decision-grade 工作放在远大于本 Pilot 的规模上，详见 [`../../research/v0.3-data-volume-and-metrics-recommendation.md`](../../research/v0.3-data-volume-and-metrics-recommendation.md)。因此本周不得发布“优于其他产品”“总体能力已证明”或“生产就绪”等结论。

任务导航见 [`v0.4-todos/README.md`](v0.4-todos/README.md)。

## 1. 资源边界与前置假设

### 1.1 硬边界

- 只有一人，同时承担 Owner、Operator、Data/Eval、Reviewer 和报告编写；不存在独立复核或真正盲审。
- 主动工时最多 40h，外部审批、排队和服务等待单列 wall-clock，不通过加班补齐。
- 不在本周新建通用 adapter、完整 harness、Judge 服务或 dashboard；允许使用最小 CSV/JSON/表格和一次性脚本保存、校验与汇总证据。
- 不接 Dify/FastGPT/第二模型，不做 Quick vs Optimized，不做 model bake-off。剩余时间只能补证据、复核或处理阻断，不能临时扩 scope。

### 1.2 Day 1 必须验证的假设

- 可访问目标 MOI 租户、Native RAG 入口和目标版本，具备上传、建库、查询及保存证据的权限。
- 6 份 PDF 均可合法上传；2 份 fresh 文档必须是虚构或私有、可外发且有生成 lineage。
- 原始响应、引用、状态、时间戳和至少一种可回放 artifact 能被保存；若 trace 不可导出，只记录 observability gap。
- 若上述身份、安全或 Native path 在 Day 1 无法确认，直接 `BLOCKED`，不以别的产品替代 MOI。

## 2. Corpus、split 与问题合同

### 2.1 Corpus

- 选择 4 份已批准 existing PDF，并制作或选取 2 份带版本标识的 fresh fictional/private PDF。
- 6 份文件至少覆盖 text-heavy、table-heavy、mixed-layout 和 scan/OCR-risk 四类版式；版式是覆盖标签，不单独做统计结论。
- 2 份 existing 文档进入 dev/smoke；其余 2 份 existing + 2 份 fresh 进入 scored。按 document family/near-duplicate component 切分，dev 与 scored 不得共享 family。
- manifest 至少包含：
  `dataset_id,document_id,path,sha256,bytes,pages,language,document_family,version,layout_tag,egress,license,split,fresh_control`。
- Gold 只从冻结文档和原始材料构建，不能根据 MOI 输出回写。

### 2.2 问题数量与配额

**Smoke/dev：6 题**

- 只验证 ingest、query、response/citation capture、错误分类和 rubric 可操作性。
- 结果不进入 scored 分母，不用于宣传产品质量。

**Sealed scored pilot set：20 题**

| 互斥主类型 | 数量 |
|---|---:|
| 单文档、单证据 | 6 |
| 单文档、多证据 | 4 |
| 跨文档综合 | 4 |
| 表格/视觉定位 | 2 |
| 不可回答 | 4 |
| **合计** | **20** |

另冻结以下正交标签：

- fresh scored = **4**；
- answerable = **16**，unanswerable = **4**；
- citation-required answerable = **10**；
- 每题记录 `question_id,question_family_id,analysis_cluster_id,answerability,negative_reason,citation_required,scored_reference_claims,critical_required_claims,evidence_sets,source/page/span/bbox/hash,fresh_control`。

每个 answerable question 至少有一个非空 `scored_reference_claims`，每个 claim 至少有一套可复核 Gold evidence set。空 claim 集、缺 evidence lineage 或无法确定 answerability 的题在冻结前删除或重写；冻结后发现则走全局 `question_invalid`，不得按结果选择性删题。

## 3. Calibration、冻结与单人偏差控制

1. Day 2 对 6 道 Smoke 各运行一次，并在看 scored 结果前预选 2 个复跑 question ID。
2. Day 3 先完成这 2 题的第二次运行，形成 **8 calibration outputs**；随后在任何 scored output 产生前打乱输出顺序，按草拟 rubric 独立标注，再修订并冻结 rubric、阈值、N/A 规则和示例；记录 freeze hash。单系统场景不声称 system blind。
3. 同时预注册 6 道 scored question 的 self-audit sample；每题固定审查两个 repeat，共 **12 rows**。抽样需覆盖 fresh、unanswerable、citation-required 和主要题型。
4. Day 4 scored run 后先完成全量主判分；Day 5 才重新检查这 12 rows，记录 label change count 和理由。自审只能发现内部不一致，不能替代独立 reviewer、QWK 或 adjudication。
5. 冻结后不得修改题目、Gold、rubric、run order 或阈值来适应 MOI 输出。必须修改时建立新 freeze id，旧记录保留，本轮最高只能 `DIAGNOSTIC_ONLY`。

## 4. 运行合同

- 仅运行 MOI Quick-start Native path。
- 20 道 scored questions 各做两次 initial repeat；每次使用 fresh session，repeat 2 使用预先冻结的轮换顺序。
- 主分母固定为 `20 questions × 2 repeats = 40 initial attempts`。Smoke、calibration、自审和 retry 不增加主分母。
- 每个计划请求第一次发出即为 initial attempt。产品/API timeout、解析错误、空响应或服务错误保留在主分母中，initial Pilot-TDAS=0。
- 每个失败最多允许 1 次 retry，仅用于 recoverability 诊断；不得替换 initial response 或 initial score。
- benchmark-side 录入/脚本故障可标 `run_invalid` 并 replacement，但须保留原 run、原因、hash 和替代 lineage；产品故障不能标 invalid。
- 每个 attempt 至少记录：
  `run_id,batch_id,system_id,condition,question_id,repeat_id,session_id,start_at,end_at,status,error_code,latency_ms,response,citations,source_artifacts,retry_of,artifact_hash`。
- retrieved chunks/rank/qrels 不可真实导出时，所有 trace-only 指标写 `N/A`，reason=`TRACE_UNAVAILABLE`；不得从最终回答或 citation 反推 retrieval trace。

## 5. 指标与判分

### 5.1 Pilot-TDAS

对每个 `(question_id, repeat_id)` 计算一个二元 Pilot-TDAS。

先把 answerable response 拆成原子、可核验的 factual claims，去除完全重复的表述；寒暄、纯格式文本和不包含事实主张的免责声明不进入 eligible set。三个核心 component 固定为：

- **Correctness** = `Σ factual-claim label / eligible canonical response factual claims`，其中 `correct=1`、`partially_correct=0.5`、`incorrect=0`；真值域为冻结问题与 selected corpus。answerable 空回答、直接拒答或零 eligible claims 时为 0。
- **Reference-claim Recall** = `被回答语义完整覆盖的 scored_reference_claims / 全部 scored_reference_claims`；partial coverage 不计命中，`critical_required_claims` 另做 100% gate。answerable 的 scored set 在 freeze 时必须非空；无覆盖时为 0。
- **Gold-evidence Support** = `被至少一套冻结 Gold evidence set 完整支持的 eligible canonical response factual claims / 全部 eligible canonical response factual claims`。answerable 空回答、直接拒答或零 eligible claims 时为 0；不得从产品 citation 或输出反向补写 Gold。

**Answerable attempt 通过条件：**

1. required evidence 已进入 searchable-ready 状态；
2. initial request terminal success；
3. Correctness ≥ 0.8；
4. 所有 `critical_required_claims` 被覆盖，且 Reference-claim Recall ≥ 0.8；
5. Gold-evidence Support = 1；
6. 无 critical contradiction、无已验证 scope violation；
7. citation-required 题的 Answer-claim Citation Coverage = 1，且所有提交引用均 locator/resolvable、完整支持关联 claim；
8. 非 citation-required 题若主动提交伪造、不可解析或不支持关联 claim 的引用，也判 Pilot-TDAS=0。

**Unanswerable attempt 通过条件：**

- 明确拒答或说明证据不足；
- 理由与冻结的 `negative_reason` 一致；
- 不输出无支持事实或伪造引用。

产品失败、空答案和错误拒答的 Pilot-TDAS 及适用的 answer-quality scores 不得记 N/A，均按上述规则为 0；但结构性零分母的 citation components 仍按下述 N/A 规则记录。零 submitted citations 时：

- locator validity 与 citation entailment precision 为 `N/A`，reason=`NO_SUBMITTED_CITATION`；
- citation-required 题的 coverage=0，因此 Pilot-TDAS=0；
- 非 citation-required 题的 coverage 为 N/A，由其他质量 gate 决定。

### 5.2 核心指标

| 层 | 本周必须评估 |
|---|---|
| Validity | 文件/页/题/attempt 计划数与实际数、hash、invalid/replacement、缺失字段、N/A reason |
| Readiness | accepted-file/page、processed/indexed/searchable-ready、Gold evidence preservation probe、source/page provenance、build time |
| Answer | Pilot-TDAS、Correctness、critical-claim coverage、Reference-claim Recall、Gold-evidence Support、critical contradiction、unanswerable success、false refusal |
| Citation | locator/resolvability、entailment precision、answer-claim coverage、伪造/越界 citation count |
| Reliability | initial availability、timeout/error、retry recovery（诊断）、两 repeat 同时通过/翻转 counts、P50/P95 latency |
| Operability | Time-to-First-Searchable-Corpus、Time-to-First-Trusted-Answer、active human minutes、intervention count、configuration error、diagnostic quality、recoverability |
| Trace-only | Evidence Recall@K、complete evidence-set recall、context precision/faithfulness/utilization、trace completeness；仅在真实 trace+rank+qrels 存在时计算 |

### 5.3 汇总口径

- 所有离散指标必须同时给 numerator、denominator 和 reasoned exclusions。
- 对 question-level 二元指标，可按每个 repeat 的实际 eligible distinct questions 给 Wilson 95% **描述区间**；Pilot-TDAS 每个 repeat 的 N 固定为 20。
- 两个 repeat 先按同一 question 取 mean，再对 20 个 question 做宏平均；该 two-repeat mean 不生成 Wilson 区间。
- claim/citation-level比例只报原始分子、分母和 rate，不把相关 claims 当独立样本生成 CI。
- reliability 另报 `pass/pass`、`pass/fail`、`fail/pass`、`fail/fail` 题数和输出差异案例。
- family、题型、fresh 等小切片只给 counts/rates 和案例，不下切片级结论。
- latency 仅对有完整时间戳的 terminal attempts 报 P50/P95，同时保留 timeout/error counts。
- 不做 comparator、paired product difference、显著性检验、McNemar、bootstrap、排行榜、加权总分或“overall winner”。

| 日 | 时间分配 | 当日出口 |

| Day 3：Gold、校准、冻结（8h） | 4h 完成并复核 20 questions/Gold；2h 标注 8 calibration outputs 并冻结 rubric；1h 预抽 6-question self-audit；1h 冻结 manifest、run order、阈值与 hash。 | **G2**：20 题配额、Gold、calibration、rubric、audit sample 全部在 scored 前冻结。 |
| Day 4：两次 scored run（8h） | 2.5h repeat 1；2.5h repeat 2；3h coverage 对账、规范化输出并开始主判分。 | **G3**：40 initial attempts 均有 status/raw/artifact；产品失败留在分母。 |
| Day 5：判分、复核、报告（8h） | 1.5h 完成主判分；1h 复核 12 self-audit rows；1.5h 算指标/失败分类/案例；2h 报告、结论、下一轮清单；2h contingency 只补证据/复核/归档。 | **G4**：结果可重算、限制清楚、结论等级唯一；不得用 contingency 扩题或接 comparator。 |

## 7. Gate、降级与停止规则

| Gate | 通过条件 | 未通过时 |
|---|---|---|
| G0 Identity/Safety/Scope | 身份、权限、Native path、egress、6-file manifest 和证据保存可验证 | 安全/权限/身份问题=`BLOCKED`；不改测其他系统 |
| G1 Native Journey/Smoke | 6 files 有明确 ready/failure 状态；6 Smoke 可发出并保存 raw/status | `DIAGNOSTIC_ONLY`；只写 journey/blocker，不进入 scored |
| G2 Dataset/Rubric Freeze | 20题、8 calibration、Gold/rubric/audit/run order/hash 全部冻结 | `DIAGNOSTIC_ONLY`；不得边跑边补 Gold |
| G3 Scored Run | 40 个 initial units 均有可追溯去向；两 repeat 完整 | 缺第二 repeat或无法对账=`DIAGNOSTIC_ONLY`；产品失败本身仍是有效零分 |
| G4 Score/Audit/Report | 全量主判分、12-row self-audit、核心指标、failure taxonomy、限制和 artifacts 可重算 | `DIAGNOSTIC_ONLY` 或证据不可修复时 `INVALID` |

资源不足时按以下顺序处理：

1. 删除所有未冻结的可选 trace 深诊断和额外案例；
2. 不增加文档、题目、retry、配置或外部产品；
3. 优先保住已冻结 20 题的两次 repeat、全量判分和结果账本；
4. 若第二 repeat 或核心证据仍无法完成，停止并降级为 `DIAGNOSTIC_ONLY`，不得通过缩小分母伪装完成。

## 8. 结论等级

### `PILOT_COMPLETE`

G0–G4 全部通过；40 initial attempts、20题主判分、8 calibration、12-row self-audit、核心指标和 raw evidence 可重算。产品失败可以存在且照常计分。该状态只表示本次 MOI Pilot 执行完整，不表示生产就绪或优于其他系统。

### `DIAGNOSTIC_ONLY`

Native journey 已产生有用证据，但 G1–G4 任一核心项不完整，例如 Gold/rubric 未冻结、只完成一次 repeat、分母无法完整对账或报告证据不足。可以描述失败模式和下一步，不能发布 benchmark 质量结论。

### `BLOCKED`

MOI 身份、权限、Native path、数据授权或安全条件无法满足。交付 blocker memo、已有证据、责任边界和解锁条件，不给零分或产品优劣判断。

### `INVALID`

冻结/hash 被破坏、关键 Gold/schema defect 无法全局修复、benchmark-side 运行 lineage 不可追溯，导致结果不能解释。保留原始记录并说明影响范围，不用部分结果冒充 Pilot。

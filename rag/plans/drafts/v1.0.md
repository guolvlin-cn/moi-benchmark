## 2 研究问题、estimand 与非目标

| ID | 问题 | Estimand |
|---|---|---|
| Q-01 | Native journey 是否可复现 | first-attempt readiness 与 terminal success |
| Q-02 | 回答是否正确且有证据 | question-level TDAS 与六层 scorecard |
| Q-03 | 重复是否稳定 | 同题 repeat 的 pass/pass、翻转和失败率 |
| Q-04 | 上游检索影响多少 | 同一外部 generator envelope 下 retrieved-context 与 Gold-context 差 |
| Q-05 | 规模化代价是什么 | 独立性能轨的 latency/throughput/error/censoring |

非目标：生产就绪、跨供应商总冠军、加权总分、未经预算匹配的 Optimized 排名、从引用反推检索、把小切片当总体结论。

## 3 系统、资格与 attempt 合同

每系统需冻结 `system_id,vendor,product,version,tenant,model,embedding,identity,capability,license,egress,quota,budget_hash`。资格只依 identity/capability/budget，在 formal 前冻结；不按 pilot 分数淘汰。

| 合同 | 规则 |
|---|---|
| first-attempt | 首次发出请求即计入分母，即使 timeout/空答/服务错误 |
| retry | 每次失败最多 1 retry；仅 recoverability 诊断，不替换初次 |
| invalid | 仅 benchmark-side schema/脚本/lineage 缺陷；保留原 run、原因、hash |
| product failure | 留在分母并按 0 计质量，不标 invalid |
| trace | 无真实 rank/qrels/context trace 则 `N/A, TRACE_UNAVAILABLE`，不推断 |
| reset | 每题 fresh session；运行顺序、reset、warm-up 写入 ledger |

| 来源 | 能做什么 | 不能做什么 | 启用 gate |
|---|---|---|---|
| 两篇本地 PDF/论文 | 研究背景与可复核方法 | 不自动成为 native Gold | license、hash、引用定位 |
| EnterpriseRAG | flattened JSON 企业文本检索/问答 | 不作 PDF parser | schema 与任务对齐 |
| FAB | Gold Context/reader | native 需 corpus+code+license | 三项 gate 全通过 |
| MIRAGE | Base/Oracle/Mixed 正式条件 | Hard Negative/Contradictory 仅扩展 | 条件标签固定 |
| RAGPerf | 性能结构参考 | 不作质量排名证据 | 仅方法启发 |
| 四篇 blogs | 工程假设/指标灵感 | 不作排名证据 | source review 登记 |
| parser/retrieval/reader benchmarks | 分层独立报告 | 不与整机榜合并 | layer、任务、数据集可比性 |
| optional performance corpus | 只扩展建库/查询负载到 1,000 docs | 不进入质量分数或 Gold | 额外 800 docs 全部有 license/egress/hash，五系统同一 manifest |

## 6 运行条件正交矩阵

| 条件 | 平台维度 | generator | context | 用途 |
|---|---|---|---|---|
| Quick Native | 有 | 平台默认 | 平台真实 | 主榜/pilot |
| Frozen Optimized Native | 有 | 平台配置 | 平台真实 | 预算等价才开次榜 |
| Retrieved-context replay | 有（上游） | 统一外部 | 各平台真实 context | 上游诊断，非整机榜 |
| Shared Gold Context | 无 | 统一外部 | Gold evidence | oracle；S1=`20×1×2=40`，formal=`600×3=1800` |
| No-context | 无 | 同一外部 | 空 | 先冻结 `Q_nc,R_nc`；分母=`Q_nc×R_nc` |
| Noise | 无 | 同一外部 | 预注册扰动 | 先冻结 `Q_noise,C_noise,R_noise`；分母=`Q_noise×C_noise×R_noise` |
| Performance | 有 | 固定 workload | 固定读写 mix | 独立性能榜 |

Formal 的 Quick Native 分母为 `600×N×3`；N=5 时为 9,000。Optimized 只有在五个候选系统都满足同一调优合同并整体启用时才另跑 `600×N×3`，否则不出 Optimized 榜。Retrieved-context replay 为 `600×N_trace×R_replay`，默认建议 `R_replay=3`，但必须在 G2 冻结；`N_trace` 只包含能导出真实 context trace 的系统，其他系统保留 `TRACE_UNAVAILABLE` 行。

## 7 Gold、lineage 与修订

Gold 每题至少含 `question_id,question_family_id,analysis_cluster_id,answerability,claims,critical_claims,evidence_sets,document_id,page,bbox,span,file_sha256,evidence_sha256,gold_version,freeze_id`。family 不能跨 split 泄漏；egress/license 先过 gate。任何修订新建 `gold_version`，记录旧新 diff、影响题目和全局重跑范围。

## 8 TDAS 六层 scorecard

六层为：`validity/readiness`、`answer quality`、`citation/evidence`、`reliability`、`operability`、`trace/diagnostic`。每层报告 numerator/denominator、失败、N/A reason；TDAS 不压成冠军分。Native 对 shared Gold 仅报告 descriptive native-to-shared-oracle reference delta。

## 9 Judge、审计、统计

Judge 先冻结 rubric 与 calibration，再盲化 system labels；calibration 的 QWK 必须 ≥0.60。formal 预注册 120 个不同问题用于双人盲审，每个问题覆盖所有系统的同一预注册 repeat，分歧进入 adjudication。question-level paired comparison 以 `analysis_cluster_id` 为唯一 bootstrap 单位，固定 10,000 replicates、seed 与 CI 方法；`family_id` 只做 split 泄漏隔离。Wilson 区间只用于描述性 pilot；小切片只报 counts/rates。

## 10 Gate、停止与降级

G0 身份/安全/范围；G1 Native readiness；G2 Gold/rubric freeze；G3 attempt/ledger 完整；G4 judge/统计/报告；G5 性能环境。失败顺序：停止扩题→保住冻结集与分母→保留 raw/decision log→降为诊断；不可通过删失败或缩分母伪装完成。

## 11 资源、公式与里程碑

不同 condition 的维度不同，禁止用一个笼统笛卡尔积估算总量；必须分别采用第 6 节公式。S0 固定 1×5×8h=40h；S1 约 10–15 active person-days；S2 约 3–6；S3 pilot 约 8–15、完整 200/1000 约 30–50 人日/6–8 周；S4 约 3–4 周并按每个 condition 的分母和 Judge 量预算；S5 约 1–2 周。S4 Quick N=5 为 `600×5×3=9000`，Optimized 若启用则另计同量 formal attempts 和冻结的 dev budget。

## 12 交付目录

`datasets/{source,manifest,gold,freeze}`；`systems/{identity,capability,budget}`；`runs/{ledger,raw,context,artifacts}`；`reports/{pilot,formal,replay,performance}`；`decisions/{freeze,scope,invalid,stop}`。每份报告可由 ledger/hash 重算。

## 13 风险

权限/版本漂移→G0 identity freeze；Gold 泄漏→family/hash 双审；trace 不可观测→N/A；预算不等价→不开 Optimized；平台升级→new version + full rerun；服务限流→记录 censoring，不替换初次。

## 14 与旧计划、修订摘要

相对 v0.4：保留 MOI-only 40h Pilot 原样为 S0，新增多系统与 formal 的条件化路线；相对 v0.3/three-stage：保留 decision-grade 研究背景但把可操作合同集中到 v1.0。v1.0 修订摘要写在 decision log，包含日期、ID、旧新文本、影响与批准者。

## 16 统一 attempt 与分母示例

单题单系统两 repeats 产生两个 initial rows；超时后 retry 产生附加 row，不改变两个 initial rows。若 benchmark-side 脚本错误导致 replacement，原 row 标 `invalid`、替代 row 标 `replacement`，报告同时列出。产品返回空答案、解析失败、配额耗尽均是有效 initial failure。

Stage1 ledger 示例：

| group | systems | q×r | initial |
|---|---:|---:|---:|
| MOI Native | 1 | 20×2 | 40 |
| 四竞品 Native | 4 | 20×2 | 160 |
| Native 合计 | 5 | — | 200 |
| shared Gold Context oracle | 无 platform | 20×1 condition×2 repeats | 40 |

这 200 个 Native units 必须在 Stage 1 共同时间窗内新跑；Stage 0 的历史 MOI 40 只作流程基线，不进入 Stage 1 横向分母。No-context 与 Noise 不在上述 40 个 oracle units 中，启用时按第 6 节公式另建 ledger。

## 17 指标定义补充

`Correctness = scored factual claim labels / eligible canonical claims`；`Reference recall = fully covered scored reference claims / all scored reference claims`；`Gold support = fully supported response claims / response claims`。answerable 空答、错误拒答、产品失败均为 0；结构性无提交引用时 citation locator precision 可 N/A，但 citation-required coverage=0。

Reliability 报 `pass/pass, pass/fail, fail/pass, fail/fail`；latency 只对完整时间戳 terminal attempts 报 P50/P95，并保留 timeout/error。operability 报 active human minutes、intervention、configuration error、recovery。

## 18 Judge 与盲审流程

1. S0 继续使用 v0.4 的 8 个 calibration outputs；formal 则由 S-511 使用 dev/pilot 输出重新校准并冻结 Judge model/version/prompt/temperature/rubric，QWK≥0.60 后 S-517 才能签署 G2，随后才允许 M-132 formal run。
2. formal 运行前固定 120 个不同问题及同一预注册 repeat 的盲审样本；运行后随机化 answer rows，隐藏 system_id/condition。
3. 两名 reviewer 独立判 claims/citation 与 attempt-level pass；critical disagreement 由 adjudicator 复核并保留原标签、理由和最终标签。
4. 盲审完成后才展开系统名；任何 rubric 变更建立新 version，并触发受影响 condition 的 re-freeze/re-run。

## 19 统计报告约束

paired cluster bootstrap 只以 `analysis_cluster_id` 为 cluster，不将 claims 当独立样本；固定 10,000 replicates、seed 和 CI percentile/basic 方法。`family_id` 只用于 split 泄漏隔离。只有同一 freeze、同一题集、同一 condition 才做 paired difference。pilot 只给描述性区间，正式结果也不转成单一总冠军。

## 20 停止与降级决策树

```text
G0失败 -> BLOCKED
G1/G2失败 -> DIAGNOSTIC_ONLY，停止 scored/formal
G3失败 -> 保留已运行 raw，无法补齐则 DIAGNOSTIC_ONLY
G4失败 -> 不发布质量结论，修复或 INVALID
G5失败 -> 保留质量结果，取消性能榜
```

Pilot 的唯一状态为 `PILOT_COMPLETE/DIAGNOSTIC_ONLY/BLOCKED/INVALID`；formal 使用 `FORMAL_COMPLETE/FORMAL_DIAGNOSTIC_ONLY/BLOCKED/INVALID`。性能是 formal 质量报告之后的可选 addendum，G5 失败不改变已经成立的 formal 质量状态。

## 21 预算与现实区间

S0 仅承诺 40 active hours；S1 约 10–15 active person-days；S2 约 3–6；S3 pilot 约 8–15、完整 200/1000 约 30–50 人日/6–8 周；S4 约 3–4 周并按分母+judge 量预算；S5 约 1–2 周。未完成预算冻结不得启动相应阶段。

## 23 术语与命名规范

`Native` 指平台自身 ingest/retrieval/generation 路径；`Quick-start` 指未调优默认配置；`Frozen Optimized` 指预算等价且 formal 前冻结的调优路径；`shared oracle` 指无平台维度、由统一外部 generator 运行的 Gold/No-context/Noise 条件；`first-attempt` 指首次请求；`retry` 只做恢复诊断；`censoring` 指因时长/配额规则无法观察到完整结果。

## 24 版本与证据保留周期

所有 freeze、system、adapter、judge、hardware 和 source 都使用不可变 hash；原始 artifact 不覆盖。清理或归档必须写 decision log，并保留能重算 numerator/denominator 的最小集。任何外部服务版本变化即触发重新核验，影响 formal 时新建 version/freeze。

## 25 质量与公平预算核对

Quick 榜不包含 Optimized 尝试。Optimized 运行前必须冻结：最大 dev trials `T`、active person-hours `H`、wall-clock `W`、configuration actions `A`、API/compute/vendor-support budget、参数白名单、搜索空间和停止规则；五个候选系统任一无法满足，整个 Optimized condition 不开榜。formal Native 资格可以因 G0/capability 失败而成为 `NOT_ELIGIBLE`，但必须保留阻断行且不得按 pilot 分数淘汰。replay 仅比较共同 envelope；oracle 仅作共享参照。

## 26 报告写作模板

1. Scope、estimand、非目标、旧计划关系；
2. 系统 identity/capability/eligibility 与条件；
3. corpus/question/gold/freeze readiness；
4. planned/initial/retry/replacement 分母；
5. G0–G5 证据与唯一结论；
6. 六层 scorecard、paired statistics、切片限制；
7. replay gap、trace N/A 与公共研究分层；
8. 性能独立结果、censoring、资源；
9. 风险、decision log、下一阶段触发条件。

## 27 最终停止条件

在未通过 G2 时不得产生正式质量分；在未通过 G4 时不得发布 formal 结果；在未通过质量/功能 gate 时不得运行 S5；在任何阶段都不得用部分结果宣称生产就绪或总冠军。

## 28 决策记录最小字段

每个 decision log entry 使用 `decision_id,date,author,trigger,options,selected_rule,evidence,affected_freeze,affected_systems,re-run_scope,approval,status`。阻塞项还需 `owner,unlock_condition,next_review_at`；关闭时链接最终报告。

## 29 结果可重复性声明

报告必须说明可重复范围：相同 source hash、gold_version、system version、config hash、prompt、context budget、run order、hardware 和统计 seed。若任一条件无法复现，则结论降级为 descriptive/diagnostic，并列出不可复现字段，不以答案表面相似性补偿。

## 30 用户沟通边界

对外摘要只发布已通过 Gate 的条件化数字、分母、区间和限制；内部 blocker、quota、trace 缺失和 judge disagreement 不得省略。任何营销式比较、赢家措辞、生产承诺需退回 Program owner 与 decision log 审批。

# MOI RAG v0.3：数据量与指标建议

> 日期：2026-07-29
> 状态：Research recommendation
> 适用范围：MOI、Dify、FastGPT 的产品级 paired Native RAG benchmark
> 规范关系：本文为 `rag/plans/drafts/v0.3.md` 与 v0.3 TODO 的研究建议，不改写母计划；正式运行前仍须由 RAG Owner、Data & Eval Engineer、Reviewer 和 Approver 冻结。

## 1. 结论

1. **首选 decision-grade 目标为 480 个 hidden formal questions；360 仅为预算下限。**配套使用 120 个 dev questions（40 个 Smoke 为其子集）、60 个 calibration outputs，以及 96 个 distinct hidden questions 的正式人工 audit。`decision-grade` 仍以 dev/pilot 的 cluster-aware power simulation 通过为条件；若 480 未达到预注册 80% power，则扩至约 600 或把结论降为 estimation-only。现行 v0.3 的 180–240 formal 范围需先修订母计划并批准，不能由本文静默覆盖。
2. **公开框架的样本量不是本项目的 power 依据。**RAGBench、RAGChecker、RAGAS、ALCE、ARES 分别服务于训练 evaluator、meta-evaluation、工具演示、citation benchmark 和 PPI 校准；它们不能证明“240 题一定足够”或“必须做到数千题”。
3. **主推断继续使用 question-level paired cluster bootstrap。**三次 repeat 先在同一问题内平均，再以 `analysis_cluster_id` 成对重采样。三次 repeat 不是 3 个独立问题，不能把 480 题写成 `n=1,440`。
4. **McNemar 只作为 iid 二元样本量敏感性，不作为首版正式检验。**为了做预算，可把每个问题三次 TDAS 暂时映射成 `stable_question_success = 1{sum_r TDAS >= 2}`；但 hidden questions 在 `analysis_cluster_id` 内相关，不能把 480 题当成 480 个独立 McNemar pairs。正式推断只使用 cluster-aware simulation 与 paired cluster bootstrap。
5. **480 的目的不是制造“赢家”，而是为主要 paired 决策提供一个可验证的起始规模。**明确推荐 **Quick-start TDAS 为唯一 primary condition**，以 MOI–Dify、MOI–FastGPT 两个 primary contrasts 为一个 family；Optimized 仍完整运行，但作为 secondary/estimation 单独报告。以 10 个百分点差异、80% power、Holm 首阶双侧 `α=0.025` 规划，iid exact McNemar pairs 在 discordance `q=0.20/0.30/0.40` 下约需 196/296/394；按 1.2 design effect 粗调的最坏 raw-question 目标约为 473，因此 480 只有很小余量。若 design effect 接近 1.5，最坏目标约 591，应采用约 600 hidden；若 Quick 与 Optimized 都要作联合确认性结论，则是四个 contrasts，必须重新规划。
6. **指标必须按层分开。**TDAS 是端到端布尔北极星；Gold correctness/support、citation、unanswerable 是共同结果指标；TRACe/RAGChecker/RAGAS/ARES 中依赖实际 context 的指标仅在真实 trace 可导出时作为 Stage Diagnostics；operability、latency、cost 不折入 TDAS。
7. **N/A 只表示结构上不适用，不表示能力失败。**无 trace 是 `observability_gap`；无 citation 能力时，citation-required 题仍按 coverage=0、TDAS=0，不能用 N/A 获益。
8. **问题数不能替代独立性。**目标是 family-level split 后至少 50 个独立 `analysis_cluster_id`（dev ≥10、hidden ≥40），且任一 hidden cluster 不超过 15 题。若现有 PDF 归并 family/near-duplicate components 后达不到该约束，应补文档/独立 families，而不是继续在少数文档上堆题；这是待 dev/pilot ICC 与方差模拟复核的工程统计 guardrail，不是论文给出的固定阈值。

## 2. 一手来源对数据量的启示

| 来源 | 一手来源中的规模 | 它实际支持什么 | 对 MOI v0.3 的边界 |
|---|---:|---|---|
| RAGBench / TRACe | 12 个数据集、5 个领域，约 100k examples；论文表中约 78k/12k/11k train/dev/test。Relevance/Utilization 的作者人工细粒度复核只有随机 40 例 DelucionQA 子集。 | 大规模 evaluator 训练/验证和 span-level TRACe 标签。 | “100k”不是产品 benchmark 的最低题数；“40”也不是本地 Judge 校准充分性的普适证明。[RAGBench 原始论文](https://arxiv.org/pdf/2407.11005) |

| RAGAS | WikiEval 从 50 个 Wikipedia pages 各构造一个问题；两位 annotators 对三个维度标注并解决分歧。 | reference-free 自动指标的演示与小规模人工一致性检查。 | “reference-free”指不需要 Gold answer，并不代表 faithfulness/context relevance 不需要 retrieved context，也不证明 50 例足以校准本项目 Judge。[EACL 2024 原始论文](https://aclanthology.org/2024.eacl-demo.16.pdf) |
| ALCE | ASQA、QAMPARI、ELI5 各从 dev 随机取 1,000 例，共 3,000；人工 citation 评估从 ASQA 和 ELI5 各随机取 100 个问题。 | 端到端 citation generation 的 correctness、citation recall、citation precision 评估。 | 可借用 citation 语义和审计协议，不能把它的 NLI 自动分数直接当产品 Gold 判定。[EMNLP 2023 原始论文](https://aclanthology.org/2023.emnlp-main.398.pdf)、[作者仓库](https://github.com/princeton-nlp/ALCE) |
| ARES | 输入要求约 150 个或更多 human preference validation points 和至少约 5 个 in-domain few-shot examples；主实验常用 300 labels。论文消融显示低于约 100–150 labels 时难以区分模拟系统。 | 用领域合成数据训练 Judge，再用 PPI 和人工 validation set 校准系统级区间。 | 不能作为“零人工标注”的即插即用 evaluator；本项目建议的 60 calibration outputs 也不等价于 ARES/PPI 的 150–300 labels。[NAACL 2024 原始论文](https://aclanthology.org/2024.naacl-long.20.pdf) |

因此，v0.3 的数据量应由四件事共同决定：产品运行预算、目标切片覆盖、预注册最小关注差异（minimum effect of interest）下的 paired power，以及 `analysis_cluster_id` 内相关性；不应从任一公开 benchmark 的总规模倒推。

## 3. 推荐的指标分层

### 3.1 Layer 0：样本、有效性与能力账本

所有 scorecard 之前先报告：

- `distinct_questions`、`analysis_clusters`、`initial_attempts_expected/observed`；
- `question_invalid`、`run_invalid`、replacement、product/API failure；
- `citation_capability`、`trace_available`、rank/score/source-map 可用性；
- public/fresh、Quick/Optimized、answerable/unanswerable 的独立分母；
- 每个 N/A/gap 的 reason code。

这是防止“能力缺失变成高分”和“系统选择性删题”的前置层。

### 3.2 North-star：端到端北极星

对系统 `s`、Native condition `c`、问题 `q`、repeat `r`，定义：

```text
TDAS_s,c,q,r =
  1{required evidence ready}
× 1{initial request success}
× 1{Correctness >= 0.8}
× 1{Reference-claim Recall >= 0.8}
× 1{Gold-evidence Support = 1}
× 1{no critical contradiction}
× citation gate
```

其中 citation-required answerable 题的 `citation gate` 为
`1{Citation Precision=1 and Required Claim Citation Coverage=1}`；非 citation-required 题为 1，但实际提交的错误/伪造引用仍单报。不可回答题使用 v0.3 的独立 strict-success 规则，不套 answerable 公式。

主估计按母计划计算：

```text
question_TDAS_s,c,q = (1 / R_q) × Σ_r TDAS_s,c,q,r
system_TDAS_s,c     = (1 / Q)   × Σ_q question_TDAS_s,c,q
paired_diff_A-B     = (1 / Q)   × Σ_q
                      (question_TDAS_A,c,q - question_TDAS_B,c,q)
```

`R_q` 通常为 3。产品 failure 是 TDAS=0；只有批准的全系统 `question_invalid` 或 benchmark-side `run_invalid`/replacement 按合同处理。

| North-star | 分母 | 需要 retrieved trace | N/A |
|---|---|---:|---|
| TDAS | 所有有效 hidden questions 的全部 scored initial attempts；先三次均值，再 question macro-average | 否；Gold/readiness/citation artifacts 足够，trace 只作归因 | 可比 Native condition 不得 N/A；产品/能力失败=0。 |
| SLO-TDAS（可选） | `TDAS=1` 且满足预冻结 latency/availability/cost 上限的 initial attempts / 全部 scored initial attempts | 否 | 未预注册 SLO 时整个指标=N/A，不得事后选择阈值。 |

### 3.3 Release-blocking core：Data Readiness 与 Gold/answer/citation

Data Readiness 先判产品是否真的把原始文件变成可搜索、可追溯的证据；UI/job 的 `ready` 文案本身不是真值。

| 指标 | 公式与分母 | 需要 retrieved trace | 与 TDAS 的关系 | N/A 规则 |
|---|---|---:|---|---|
| Accepted-file rate | `# 被产品接受的 manifest files / # eligible manifest files` | 否 | 不直接入分；拒收造成的 evidence-not-ready 会令相关 answerable attempt TDAS=0 | Formal PDF 集不得 N/A。 |
| Accepted-page rate | `# 成功进入产品处理路径的 manifest pages / # eligible manifest pages` | 否 | 同上 | 只有无 page 概念的非分页格式才可 N/A；本版 PDF 不可。 |
| Build/ready success | `# processed ∧ embedded ∧ search-probe-pass files / # eligible manifest files`；另按问题计算 `ready_evidence(q)=1{每个 required claim 至少一套完整 alternative set 的全部 source 均 ready}` | 否；需要 job/artifact 与 search probe | `ready_evidence(q)` 是 answerable TDAS gate | 状态不可观察要记 `observability_gap`；不能把 UI “完成”当成功或用 N/A 放过 gate。 |
| Ready-status truth / false-ready | `# UI/API 标 ready 且 search probe 通过的 files / # 标 ready files`；`false_ready_rate=1-truth rate` | 否 | 当前 v0.3 为诊断；建议作为 readiness Gate 的反例检查 | 没有 ready 状态字段时 N/A，并记录能力缺口。 |
| Gold Evidence Preservation | `# 在 parsed/indexed/retrievable representation 中语义与定位均存活的 audited Gold evidence items / # eligible audited Gold evidence items` | 否；需要 artifact 或确定性 probe | 不直接加权；缺失会通过 `ready_evidence`/Gold support 造成 TDAS 失败 | 产品不导出 artifact 时可 N/A，但必须保留 probe 结果和 gap。 |
| Provenance preservation | `# file/hash/page/span/bbox 映射正确的 audited surviving evidence items / # audited surviving evidence items` | 否 | 无效 locator 会使对应 citation 无效；其余作为 stage failure | 源系统结构上没有 page/bbox 时相应字段 N/A，但 file/hash/source locator 不能整体 N/A。 |
| Initial request success | `# 有合规 terminal response 的 scored initial attempts / # all scored initial request units` | 否 | 每次 attempt 的硬 gate；产品 timeout/API failure=0 | 不得 N/A；只有合规 `run_invalid` replacement 不进入被替换分母。 |

以下口径保持 v0.3 规范，不让候选框架重定义公式：

| 指标 | 公式与分母 | 需要 retrieved trace | 与 TDAS 的关系 | N/A / 空集 |
|---|---|---:|---|---|
| Correctness | `Σ score(response factual claim) / # eligible canonical factual response claims`，score 为 1/0.5/0 | 否；依据冻结 question + selected corpus/Gold | `≥0.8` gate | answerable 空答案、拒答或空分母=0。 |
| Reference-claim Recall | `# 被语义正确完整覆盖的 required reference claims / # required reference claims` | 否 | `≥0.8` gate | unanswerable 不套用。answerable 的 required 集为空会让 TDAS gate 无法复算，必须在 freeze validator 中拒绝；若冻结后才发现，按全系统 `question_invalid` 的 dataset-defect 流程处理，不能作为普通 N/A 进入分数。 |
| Gold-evidence Support | `# 被任一有效 Gold evidence set 完整支持的 eligible response factual claims / # eligible response factual claims` | 否 | 必须=1 | answerable 空答案、拒答或空分母=0。 |
| Critical contradiction | `1{存在改变答案的 required Gold claim/数值/实体/版本/约束冲突}`；另报 contradiction count | 否 | 必须=0 | answerable 不得 N/A。 |
| Citation Precision（当前合同） | `# valid submitted claim citations / # all submitted claim citations`；valid 同时要求 locator、scope 与 entailment | 否；需要 citation artifact/source map，不等于 retrieval trace | citation-required answerable 必须=1 | 当前 v0.3 约定零提交=1，但必须同列 submitted=0 与 coverage；建议下版改为 N/A，见 §9。 |
| Required Claim Citation Coverage（当前合同） | `# 有至少一条 valid citation 的 citation-required response claims / # citation-required response claims` | 否 | citation-required answerable 必须=1 | 结构上没有需引用 claim 才 N/A；题目必引但缺引=0。 |
| Unanswerable success | `# strict correct refusals / # unanswerable initial attempts`，且不得有 unsupported fact/伪造 citation | 否 | unanswerable TDAS 的质量 gate | 只对 unanswerable；answerable=N/A。 |
| False refusal | `# answerable initial attempts that refuse / # answerable initial attempts` | 否 | 不另作 gate，但对应 answerable attempt 通常 TDAS=0 | answerable cohort 不得 N/A。 |

这里有四个需要母计划批准后才能生效的语义修正，本文不把它们伪装成现行规则：

1. `required claims` 与 Recall 只要求 `≥0.8` 存在命名冲突。建议拆成 `critical_required_claims`（每项必须 100%）和 `scored_reference_claims`（总体 Recall ≥0.8），或把后者改名为非“required”的 reference claims。每个 answerable question 必须至少有一个有效 scored/critical reference claim；空集是 dataset/schema defect，不是可计分的 N/A。
2. 当前 Correctness 实质上是 **response-claim precision**。建议明确真值域是“冻结 question + selected corpus”，并为“参考答案未枚举、但由 selected corpus 真实支持”的额外 claim 设独立、盲化双审通道；不得因看到某产品输出而回写 required Gold。
3. Citation 建议拆为 `Locator/Resolvability Validity`、`Citation Entailment Precision`、`Answer-claim Citation Coverage`，必要时再加 `Required-reference Citation Recall`。零 citation 时 semantic precision 应为 N/A、必引 coverage=0；这与当前 v0.3 的 empty precision=1 明确冲突，属于 normative change。
4. 建议新增 rubric-based `Instruction Compliance / Answer Relevance`，或 `Extraneous Supported Claim Rate = #真实受支持但不响应问题的 claims / #受支持 response claims`，避免“真实但离题/冗余”的内容穿透现有 gates。RAGAS/ARES 只说明 relevance 与 factuality 是不同构念，不构成直接采用其自动分数的依据。

ALCE 的 citation recall 是“每个 response statement 是否被其 citations 联合完整支持”的平均；citation precision 是逐 citation 判断是否支持其关联 statement。其论文也明确指出自动 NLI 难以识别 partial support。v0.3 因而应保留 `full/partial/none` 原始判定、以 full support 作为 gate，并对关键引用做人工审计。[ALCE 论文 §3.3 与限制](https://aclanthology.org/2023.emnlp-main.398.pdf)

### 3.4 Common diagnostics：仅在输入真实可用时计算

先区分三个对象：

1. **Gold evidence**：数据集预先冻结的 source/page/span/hash；
2. **retrieved trace/context**：产品本次请求实际给 generator 的 chunks/ranks/scores；
3. **user-visible citations**：回答向用户显示的来源。

三者不得互相推断。推荐字段和来源映射如下：

| 诊断 | 公式/语义与分母 | 需要真实 trace | 与 TDAS 的关系 | N/A 规则 |
|---|---|---:|---|---|
| Evidence Recall@K | `K 内命中的 eligible Gold evidence items / # eligible Gold evidence items` | 是，且需要 rank+qrels | 不进入 TDAS | 无真实 top-K trace 或 qrels=N/A。 |
| Complete Evidence-set Recall@K | `# 至少一套 alternative evidence set 全部在 K 内的 required claims / # required claims` | 是 | 不进入 TDAS | 无 trace=N/A；unanswerable=N/A；answerable required 集为空是 dataset defect。 |
| Context Precision@K | `# top-K chunks 中含至少一个 required Gold claim 的 chunks / # returned chunks up to K` | 是 | 不进入 TDAS | 无 trace/qrels=N/A；不得从 citations 代算。 |
| MRR | `Σ_q 1/rank(first relevant item) / # eligible queries`，未召回相关项记 0 | 是，且需要真实 rank+binary qrels | 不进入 TDAS | rank 或匹配 collection 的 qrels 缺失=N/A。 |
| nDCG@K | `Σ_q DCG@K/IDCG@K / # eligible queries`，`DCG@K=Σ_i(2^rel_i-1)/log2(i+1)` | 是，且需要 rank+graded qrels | 不进入 TDAS | rank、graded qrels 或可定义的 IDCG 缺失=N/A。NIST TREC 也要求 test collection 与 qrels 匹配。[TREC qrels 说明](https://trec.nist.gov/data/reljudge_eng.html) |
| Runtime-context Faithfulness | `# 被实际 retrieved chunks 完整支持的 response factual claims / # eligible response factual claims` | 是 | 不进入 TDAS；不能替代 Gold support | 无 trace=N/A；空 response-claim 集=N/A，但核心 Gold support 仍按 0。 |
| Context Utilization | `# 被回答使用的 eligible retrieved relevant content / # eligible retrieved relevant content`；冻结 span/claim 单位 | 是 | 不进入 TDAS | 无 trace=N/A；相关 context 空集=N/A。 |
| Scope violation | `# 使用 excluded file/disabled evidence 的 attempts / # scope-eligible attempts`，并保留 violation count | citation 可发现，trace 可归因 | 当前合同通过 citation/support 间接失败；建议任何已验证 violation 直接 TDAS=0（normative） | 没有显式 scope 的题=N/A；能力不可观察是 gap，不是 pass。 |
| Trace/lineage completeness | `# trace-capable attempts 中 chunk→source/hash/page/span/run lineage 必填字段完整的 attempts / # trace-capable attempts` | 是 | 不进入 TDAS | 产品确认无 trace 能力=N/A + `observability_gap`；有能力但丢字段=0。 |

#### TRACe 的精确定义及命名边界

对 retrieved document `d_i`，相关 span 为 `R_i`、被回答使用的 span 为 `U_i`：

```text
Relevance    = Σ_i Len(R_i)       / Σ_i Len(d_i)
Utilization  = Σ_i Len(U_i)       / Σ_i Len(d_i)
Completeness = Σ_i Len(R_i ∩ U_i) / Σ_i Len(R_i)
Adherence    = 1{回答所有部分均由 context 支持}
```

RAGBench ground truth 使用 sentence length，但论文允许 character/token/sentence length，因此实现必须冻结单位。TRACe Completeness 是“已召回的相关 context 中有多少被回答使用”，**不是** v0.3 的 Reference-claim Recall。[RAGBench 论文 §3.2](https://arxiv.org/pdf/2407.11005)

#### RAGChecker 的可复用部分

RAGChecker 把 model answer `m` 与 ground-truth answer `gt` 拆成 claims：

```text
overall precision = # response claims entailed by gt / # response claims
overall recall    = # gt claims entailed by m       / # gt claims
claim recall      = # gt claims entailed by retrieved chunks / # gt claims
context precision = # relevant retrieved chunks / k
faithfulness      = # response claims entailed by chunks / # response claims
context utilization =
  # retrieved gt claims also present in response / # gt claims present in chunks
```

它的 overall precision/recall 只需 question、ground-truth answer 和 response；retriever/generator diagnostics 必须有实际 chunks。官方仓库也将 `retrieved_context` 作为输入，因此“无需 Gold context”不等于“无需 runtime trace”。[RAGChecker 论文 §3 与 Appendix B](https://proceedings.neurips.cc/paper_files/paper/2024/file/27245589131d17368cccdfa990cbf16e-Paper-Datasets_and_Benchmarks_Track.pdf)、[官方仓库](https://github.com/amazon-science/RAGChecker)

#### RAGAS 与 ARES 的位置

- RAGAS faithfulness 为 `# context-supported answer statements / # answer statements`；answer relevance 为从答案反生成问题与原问题的平均 embedding cosine；context relevance 为 `# extracted relevant context sentences / # context sentences`。后两项不能替代 Gold correctness/Reference-claim Recall。[RAGAS 论文 §3](https://aclanthology.org/2024.eacl-demo.16.pdf)
- ARES 的三个二元 Judge 分别评 context relevance、answer faithfulness、answer relevance；其 PPI 需要领域 passage set、约 150+ 人工 validation labels 和更大的未标注预测集。首版可把 ARES 作为后续 evaluator-engineering 方案，而不是 common scorecard 的默认实现。[ARES 论文 §3](https://aclanthology.org/2024.naacl-long.20.pdf)

### 3.5 Reliability-performance

| 指标 | 公式与分母 | 需要 trace | 与 TDAS 的关系 | N/A 规则 |
|---|---|---:|---|---|
| First-pass availability | `# initial requests 获得合规 terminal response / # all scored initial request units` | 否 | 单次 initial success 是 TDAS gate；本比例本身不替代 TDAS | 不得 N/A。建议结果模板统一用 “availability”，避免与 trusted success 混名。 |
| Final availability | `# request units 在 initial 或≤2次 retry 后至少一次成功 / # all scored initial request units` | 否 | 不进入 TDAS；retry 不替换 initial | 不得 N/A；未 retry 仍留在分母。 |
| Timeout/error rate | `# timeout 或 product/API error initial attempts / # all scored initial attempts`，按 error code 分层 | 否 | 对应 initial TDAS=0 | 不得 N/A。 |

## 5. 数据量与区间精度

### 5.1 Decision-grade 数据账本

在现有 46 PDF 全部通过 hash/license/egress 复核的前提下，文档目标是 **58 份：46 份 public baseline + 12 份 fresh-control**。建议约 10 份 public documents 进入 dev、约 36 份 public documents 加 12 份 fresh 进入 hidden；切分必须移动完整 family/near-duplicate components，实际数量以 component 隔离优先，任何偏差在 freeze 前记录。

这个 58 是条件性目标，不是“PDF 数=独立样本数”：family-level split 后应目标 **≥50 个 independent analysis clusters（dev ≥10、hidden ≥40）**，且单一 hidden cluster ≤15 题。若 46+12 份文档因版本链/近重复归并后达不到，应新增合规文档与独立 families，直至满足 guardrail；不得把同一文档多出题当作补足独立性。最终 cluster 阈值仍由 dev/pilot 的 ICC、paired variance 与 simulation 复核。

| 数据/审计集合 | 首选数量 | 角色与边界 |
|---|---:|---|
| Corpus documents | 条件性目标 58 | 46 public 全复核 + 12 fresh；若不足 ≥50 total/≥40 hidden clusters 则补独立文档。 |
| Dev questions | 120 | 只用于配置/Judge/adapter 开发和 variance/ICC 估计；不进入 formal 分数。 |
| Smoke questions | 40 | **是 120 dev 的子集**，不是额外 40；覆盖 10–15 个 document families。 |
| Hidden formal questions | 480 | 三产品、Quick/Optimized、三次 scored initial repeats 的共同 paired set。 |
| Fresh-control hidden questions | 96 | 是 480 hidden 的正交标签，可与五个互斥主类型重叠；不是额外题数。 |
| Judge calibration outputs | 60 | 按 answerability、题型、系统、condition 和 score strata 分层；不等同于 60 个独立 questions。 |
| Formal human audit | 96 distinct hidden questions | 等于 480 的 20%；每题覆盖所有 system×condition 的同一预注册 repeat。争议扩审不挤占 96。 |

问题总量因此是 **600 distinct questions = 120 dev + 480 hidden**；Smoke 不另加，fresh 也不另加。

若只能执行 360 hidden，应把它标为预算下限而不是等价 decision-grade 方案。其 audit 下限按 20% 为 72 distinct questions；dev、calibration 和 Smoke 不应同比缩水来“补” formal。

| Hidden formal N | 单文档单证据 35% | 单文档多证据 20% | 跨文档 15% | 表格/视觉 10% | unanswerable 20% |
|---:|---:|---:|---:|---:|---:|
| 360（预算下限） | 126 | 72 | 54 | 36 | 72 |

### 5.3 区间精度的规划读法

若暂把每个 question 当独立二项单位，`p=0.5` 时 95% Wilson interval 的半宽为
`h = z_.975 / (2√(n + z_.975²))`。候选 formal N 的最坏半宽如下；这是精度 sanity check，不代表从有限“所有企业问题”中作了随机抽样。[NIST 对 Wilson/二项区间的说明](https://nvlpubs.nist.gov/nistpubs/TechnicalNotes/NIST.TN.2119.pdf)

| Distinct questions n | 95% Wilson worst-case half-width |
|---:|---:|
| 180 | ±7.23pp |
| 240 | ±6.28pp |
| 300 | ±5.62pp |
| 320 | ±5.45pp |
| 360 | ±5.14pp |
| 400 | ±4.88pp |
| **480（推荐）** | **±4.46pp** |

切片精度更差。下表对 180–400 使用现行 fresh 上限 40 作为“最有利旧方案”，480 使用本建议的 fresh=96；visual/unanswerable 分别按 10%/20%。所有半宽仍是假设题级独立的 Wilson 值。

| Formal n | Visual n / half-width | Unanswerable n / half-width | Fresh n / half-width | 能否独立作 10pp paired 结论 |
|---:|---:|---:|---:|---|
| 180 | 18 / ±21.0pp | 36 / ±15.5pp | 40 / ±14.8pp | 否 |
| 240 | 24 / ±18.6pp | 48 / ±13.6pp | 40 / ±14.8pp | 否 |
| 300 | 30 / ±16.8pp | 60 / ±12.3pp | 40 / ±14.8pp | 否 |
| 320 | 32 / ±16.4pp | 64 / ±11.9pp | 40 / ±14.8pp | 否 |
| 360 | 36 / ±15.5pp | 72 / ±11.25pp | 40 / ±14.8pp | 否 |
| 400 | 40 / ±14.8pp | 80 / ±10.7pp | 40 / ±14.8pp | 否 |
| **480** | **48 / ±13.61pp** | **96 / ±9.81pp** | **96 / ±9.81pp** | **仍否；只改善 rate 描述** |

480 的其他互斥配额中，n=168 的半宽为 ±7.48pp、n=72 为 ±11.25pp。尤其 visual=48 的区间仍很宽，只能方向性解释；即使 unanswerable/fresh=96 达到约 ±9.81pp 的单一 rate 精度，它们也低于两个 primary comparisons 下 McNemar 最乐观的 188 pairs，更不能在 cluster inflation 后独立声称 10pp 系统差异。若视觉或 fresh-control 需要独立比较，应设另一个有自身 power/cluster 设计的 track。

最终 TDAS/difference CI 必须使用三次 repeat 的 question mean 和 paired cluster bootstrap。Wilson 和 McNemar 只用于二元比例的 sanity check/power 规划，不能吸收 `analysis_cluster_id`、repeat correlation 或连续的 `0, 1/3, 2/3, 1` question outcome。

### 5.4 运行量与 retry 容量

480 hidden、3 systems、2 Native conditions、3 initial repeats 对应：

```text
scored initial attempts = 480 × 3 × 2 × 3 = 8,640
```

Controlled Generation、Smoke、dev tuning、calibration 和人工 audit 都不包含在这 8,640 内。正式容量至少同时列出两个场景：

| 场景 | 额外 diagnostic retries | 总请求量 |
|---|---:|---:|
| 运营规划：10% initial attempts 失败，每个失败最多 2 retry | `8,640 × 10% × 2 = 1,728` | 10,368 |
| 合同极端硬上限：每个 initial 都用满 2 retry | `8,640 × 2 = 17,280` | 25,920 |

retry 永不替换 scored initial；10% 是容量假设，不是允许的失败阈值。96-question audit 在最小“同一预注册 repeat”口径下涉及 `96 × 3 systems × 2 conditions = 576` 个 outputs；两名 reviewer 全量独立评审即 **1,152 assignments**，adjudication 和争议扩到全部 repeats 的工作另计。60 个 calibration outputs 同样由两名 reviewer 独立判定，至少 120 assignments；这 60 是 rubric/冻结 Judge 的本地 calibration 下限，不是 ARES/PPI validation set。

### 5.5 推荐 formal N 的决策

- 首选 **480 hidden + 120 dev（含 40 Smoke）+ 60 calibration outputs + 96-question audit**。
- 360 只在预算硬约束下接受，并明确降低小差异/高相关性情景的 decision power。
- 若 dev/pilot 估得 design effect 接近 1.5，改用约 600 hidden，而不是在 480 上声称足够。
- 若目标差异只有 5–7.5pp，即使 480 也可能不足；应扩样或将结论定位为 estimation-only。
- 如果一个 `analysis_cluster_id` 含多个 paired variants，名义 N 是 questions，但有效信息量同时受 cluster 数、cluster size 和 ICC 约束，不能直接等同于 question 数或简单等同于 cluster 数。应优先增加独立 document/question families，而不是在同一 cluster 内堆变体。

| 风险 | 预冻结/发布触发器 | 处置 |
|---|---|---|

## 6. 二元配对样本量敏感性（不是正式 McNemar 推断）

### 6.1 方向、2×2 表与适用边界

为做样本量 sanity check，可在问题级暂时定义：

```text
stable_question_success_s,q =
  1{TDAS_s,q,1 + TDAS_s,q,2 + TDAS_s,q,3 >= 2}
```

对系统 A/B，iid 2×2 表为：

|  | B fail | B success |
|---|---:|---:|
| A fail | `n00` | `b=n01` |
| A success | `c=n10` | `n11` |

按全文统一的 **A−B** 方向：

```text
paired net difference A-B = (c - b) / N
discordance rate q        = (b + c) / N
matched odds ratio A/B    = c / b
```

普通 McNemar 只使用 discordant pairs `D=b+c`，并要求各 pair 相互独立。[NIST McNemar 说明](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/mcnemar.htm)、[statsmodels 官方 API](https://www.statsmodels.org/dev/generated/statsmodels.stats.contingency_tables.mcnemar.html)

本 benchmark 的同一 `analysis_cluster_id` 内可以有多题，因此 480 questions **不是** 480 个独立 McNemar pairs。首版不发布 ordinary/exact McNemar p-value，也不把 `stable_question_success` 增加为正式结果指标；它只用于下面的 iid/DE 样本量敏感性。三次 repeats 同样不能当作三个独立 pairs。

### 6.2 480 questions 的 iid/DE 规划情景

推荐仅把 **Quick-start TDAS** 下 MOI–Dify、MOI–FastGPT 两个 contrasts 设为 primary family；Holm 首阶双侧 `α=0.05/2=0.025`，第二步为 0.05。Optimized 作为 secondary/estimation，保留 effect 与 cluster-bootstrap CI，但不复用确认性 power 声明。[R `p.adjust` 官方文档](https://stat.ethz.ch/R-manual/R-devel/library/stats/html/p.adjust.html)

设 A−B 目标净差 `Δ=p10-p01=(c-b)/N=0.10`、80% power、discordance `q=p01+p10`，iid 大样本规划式为：[Stata `power pairedproportions`](https://www.stata.com/manuals/pss-2powerpairedproportions.pdf)

```text
N_iid ≈ [z_(1-α/2)√q + z_(power)√(q-Δ²)]² / Δ²
```

| Discordance q | iid 近似 N | iid exact conditional N | raw target ≈ exact N×DE 1.2 | raw target ≈ exact N×DE 1.5 |
|---:|---:|---:|---:|---:|
| 0.20 | 188 | 196 | 236 | 294 |
| 0.30 | 283 | 296 | 356 | 444 |
| 0.40 | 378 | 394 | 473 | 591 |

exact 枚举的方向保持为 A−B：

```text
D ~ Binomial(N, q)
C | D ~ Binomial(D, θ)
θ = p10/q = (q + Δ) / (2q)
Power = Σ_d P(D=d) × P(exact McNemar rejects | d, θ)
```

这张表只说明：在 iid 二元近似下，如果 clustering 可粗略概括为 `DE=1.2`，480 个 raw questions 的有效信息量约为 400，略高于最坏 exact 需求 394。它**不**说明可以对 480 个相关问题直接执行 ordinary/exact McNemar；如果先聚合成约 40 个 cluster-level binary pairs，表中的样本量条件显然不成立。

design effect 可用 `DE≈1+(m̄-1)ICC` 做预算敏感性；cluster 内相关会降低有效样本量，[cluster trial 样本量方法综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC4521133/)给出同一常用形式。但正式冻结必须使用 120 dev/40 Smoke 的实际 cluster size、ICC、三次 repeat covariance、paired question-level variance、各系统 marginal rate 与 discordance，做 cluster-aware Monte Carlo simulation：完整模拟三次 repeat→question mean→paired cluster analysis→Holm decision。若 480 的模拟 power <80%，应扩至约 600 或把结论降为 estimation-only。

只有当未来设计保证每个 cluster 恰贡献一个预冻结 binary pair，且独立 cluster 数本身满足样本量要求时，才可另行预注册 McNemar sensitivity。首版正式推断仍是三次 question mean + 10,000 次 paired cluster bootstrap。

## 8. 正式冻结前检查清单

- [ ] 母计划正式批准 480 hidden 首选、360 预算下限及约 600 的高-DE升级规则；记录 minimum effect of interest。
- [ ] 46 public PDF 全量复核；加入 12 fresh，条件性目标 58 docs；family split 后 ≥50 total clusters、≥10 dev、≥40 hidden，单 hidden cluster ≤15 题，不足则补独立文档。
- [ ] 冻结 120 dev（含 40 Smoke）、480 hidden、96 fresh、60 calibration outputs、96-question audit 的 lineage 与 ACL。
- [ ] 用 dev/Smoke/pilot 或盲 pooled 数据估计 discordance、ICC、paired variance 和 repeat covariance，不看 hidden 方向。
- [ ] 冻结 Quick-start TDAS 为唯一 primary condition、两个 MOI-vs-comparator contrasts、Holm family 和 alpha；McNemar 仅保留为 iid/DE planning sensitivity。
- [ ] 用 cluster-aware simulation 验证 480 在预注册情景下的 power；DE≈1.5 时升级到约 600。
- [ ] capacity ledger 同时容纳 8,640 initial、10,368 运营规划总量和 25,920 合同极端总量。
- [ ] 人工 ledger 容纳 576 formal-audit outputs、两名 reviewer 的 1,152 assignments，以及 calibration 的至少 120 assignments；adjudication/扩审另留预算。
- [ ] paired cluster bootstrap 是首版唯一正式推断；不得把 480 个相关 questions 当作 480 个独立 McNemar pairs。
- [ ] answerable question 的 scored/critical reference claim 集非空；空集会在 freeze validator 失败或走全系统 `question_invalid`，不会产生含糊 TDAS。
- [ ] 所有 common metrics 有 numerator/denominator/eligible/empty/N/A golden cases。
- [ ] Gold evidence、runtime trace、user citation 三种对象在 schema 和 storage 中分离。
- [ ] 无 trace 时所有 retrieval-dependent 指标统一产生 `TRACE_UNAVAILABLE`，不从答案反推。
- [ ] 无 citation 能力时 citation-required TDAS 的零分路径有测试，N/A 不产生优势。
- [ ] 每张正式表都同时给 distinct questions、analysis clusters、initial attempts 和 invalid/replacement ledger。
- [ ] 对 n<50 或预注册阈值以下的 slice 不作“系统优于”结论，只报告估计、区间、失败样例和限制。

#### 7.3. Request Valuation(Benefit)

✓ Benefit Approval Procedure

✓ Benefit' <= $100,000(100K)

→ Need direct manager approval

✓ $100,000(100K)≤Benefit<$1,000,000(1M)

→ Need module head approval



✓ Benefit >= $1,000,000(1M)

→ Need fab head approval

✓ Efficiency improvement

→ Need measurable benefit in $



✓ Quality improvement

→ Need measurable benefit in $



✓ Customer satisfaction

→ Need attach related email

✓ Top management strategy

→ Need attach related email



♦ For Non-Fab related

#### 7.4. User Alignment

User contact windows should get approval from his/her organization

♦ User should get approval from all relative user organization.

For example, Fab1 DIFF operation request need be approved by Fab7 DIFF.Securtiv

Requirement need be approved by Legal or IT security team.

#### 7.5. Solution & Resource Cost Evaluation

After user request approved by all relative user contact windows, IT should provide technical solution with resource cost in $ for each request.

♦ For Fab  $ \underline{\text{related}} $(Accept request which meet below all items):

✓ Benefit approved by all relative user and management team

✓ IT Solution is feasible

✓  $ \underline{\text{ROI}} $(ROI = Benefit / IT development cost) > 1

☒ ForNon-Fab related

IT will negotiate  $ \uwave{\text{whith}} $ user to make the decision by benefit, ROI and IT resource.

# Memoria Feature 实验总览

## 一、测评目的与范围

LongMemEval 和 LoCoMo 主要评价长期记忆系统能否从历史信息中检索证据并回答问题，但不能完整反映记忆系统自身的状态管理、版本管理和质量治理能力。因此，本目录使用独立的 Feature 实验，直接验证 Memoria 的产品机制，不以最终问答正确率替代状态证据。

本轮已经完成四项正式实验：

| Feature | 核心测评对象 | 主要问题 |
|---|---|---|
| 快照与回滚 | 整个用户记忆空间 | 能否保存某一时刻的整体状态，并在后续变化后准确恢复 |
| 分支、差异与合并 | 分支及记忆版本关系 | 能否隔离并行版本、分类差异、执行无冲突合并并暴露冲突 |
| 低置信记忆治理 | 单条记忆的置信度状态 | 能否依据初始置信度、信任等级和年龄淘汰低置信记忆 |
| 重复与近重复记忆处理 | 单条写入及近重复关系 | 能否复用重复内容、处理等价改写，并保护独立事实和作用域 |

四项实验分别作用于空间、版本、质量和写入四个层级。它们的数据集、操作链和通过条件不同，因此分别报告结果，不将四项机械相加为一个“Feature 总准确率”。

此前讨论过的跨会话语义矛盾检测、信任等级自动演化与来源完整性没有纳入本轮：当前 Memoria `0.4.0` 中尚未形成普通用户可直接使用且前置条件完整的端到端链路。它们不是本轮已经完成的第五、六项实验。

## 二、统一实验配置与原则

### 2.1 Memoria 运行环境

四项 Memoria 正式实验使用同一套核心环境：

| 配置项 | 正式值 |
|---|---|
| Memoria 版本 | `0.4.0` |
| Memoria commit | `54c9114fd6888e11821edc2ee9acd570c17c5ee3` |
| 源码状态 | dirty；各 run 的 manifest 固定 source diff SHA-256 |
| Embedding | Qwen `text-embedding-v4` |
| Embedding 维度 | `1024` |
| MatrixOne 镜像 | `matrixorigin/matrixone@sha256:16ef37311b43c6882ed8242bf38b1e281d853d4f4f6163830fe10773c9fe011d` |
| 生成模型 | 关闭 |
| Reader / Judge | 不使用 |
| 数据库 | 每项正式实验使用重新初始化的独立 MatrixOne 数据目录 |
| 用例隔离 | 每个 case 使用独立用户，并设置独立金丝雀用户 |

版本号不能单独代表本次被测代码。正式结论对应上述 commit 加本地 source diff；完整哈希保存在各自 `manifest.json` 中。

### 2.2 统一实验原则

- 每个 case 都由“初始状态、操作序列、预期状态、程序化断言”组成；
- 记忆正文使用正常自然语言，不加入人工检索锚点；
- 正式结果同时检查 API 行为、活动状态、历史关系和检索可见性；
- 失败与执行错误保留在正式分母中，不静默删除；
- 数据集、Schema、runner、版本、源码状态和模型配置均被冻结；
- Smoke 仅用于验证协议能否跑通，不进入正式结果，也不保留为正式报告；
- 原始 run 目录不可覆盖，修复 runner 时只补跑缺失项并保留恢复记录；
- Feature 实验验证的是确定性状态机，不引入 Reader 或 Judge 的生成随机性。

## 三、四项实验设计与结果

### 3.1 快照与回滚

#### 测试内容

该实验把一个用户的完整记忆空间作为整体，验证：

- 创建快照后，对记忆进行新增、修改和删除，再回滚是否恢复快照状态；
- 多个快照之间能否跨级恢复；
- 回滚后能否继续写入；
- 对同一快照重复回滚是否幂等；
- 回滚后的检索可见性是否与恢复状态一致；
- 空快照、重名快照、不存在及已删除快照等边界路径是否安全。

#### 数据集与结果

| 分类 | 通过 / 总数 |
|---|---:|
| 单一操作 | 12 / 12 |
| 混合操作 | 14 / 14 |
| 多快照与跨级回滚 | 8 / 8 |
| 回滚后继续写入 | 6 / 6 |
| 重复回滚幂等性 | 4 / 4 |
| 边界及失败路径 | 6 / 6 |
| **总体** | **50 / 50（100%）** |

全部必需断言为 `501/501`。60 次预期成功回滚均恢复到指定状态；2 次预期失败回滚均返回 HTTP 404 且未改变当前状态。116 条检索记录全部首次查询即满足恢复后的可见性要求。

#### 分析

结果证明 Memoria 在本次覆盖的单用户确定性状态空间内，能够完成空间级保存与恢复，而不仅是查看单条记忆历史。新增、修改、删除、跨级回滚和回滚后继续写入均保持状态与检索一致。

该结论不覆盖多用户并发回滚、超大记忆空间、生产级容量或所有异常中断路径。

### 3.2 分支、差异与合并

#### 测试内容

该实验以从共同基线派生出的记忆分支为对象，验证：

- 主分支、子分支和同级分支是否隔离；
- Diff 是否正确分类 `added`、`updated`、`removed`、`behind_main` 和冲突；
- 无冲突追加合并是否产生正确状态；
- 重复合并是否幂等；
- 主分支与分支同时修改共同来源记忆时，是否暴露冲突；
- Diff 和冲突检查本身是否保持只读，不意外改变主分支。

#### 数据集与结果

| 分类 | 通过 / 总数 | 通过率 |
|---|---:|---:|
| 分支隔离 | 12 / 12 | 100% |
| 差异正确性 | 14 / 14 | 100% |
| 追加合并正确性 | 12 / 12 | 100% |
| 冲突检测 | 10 / 12 | 83.33% |
| **总体** | **48 / 50** | **96%** |

本次共有 `535/537` 条必需断言通过，1,125 次 HTTP 操作均返回预期成功状态，0 个系统错误。10 个真实分歧冲突全部检出，冲突召回率为 100%；两个语义等价负向对照被误报，冲突精确率为 83.33%。

#### 分析

分支隔离、结构化 Diff 和无冲突 `append` 合并表现稳定。两个失败不是漏掉真实冲突，而是把以下等价结果误判为冲突：

1. 主分支和分支都把同一来源记忆更新成相同内容；
2. 主分支和分支都删除同一来源记忆。

源码中的冲突分类主要依据共同记忆 ID 是否同时出现在两侧变更集合，没有先比较后继内容是否相同，因此会产生上述伪冲突。本实验没有验证人工或自动冲突解决，也不能外推为通用三方合并正确性。

### 3.3 低置信记忆治理

#### 测试内容

该实验直接写入确定的 `initial_confidence`、`trust_tier` 和 `observed_at`，再显式调用治理接口，验证：

- 有效置信度明显低于阈值的记忆是否被淘汰；
- 阈值以上记忆是否被保护；
- 相同初始置信度和年龄下，不同信任等级是否按各自衰减周期产生不同结果；
- 单次治理能否正确处理淘汰与保留混合批次；
- 阈值两侧、深度过期和重复治理等边界是否正确；
- 其他用户的金丝雀记忆是否不受影响。

该实验验证的是“给定记忆置信状态后，治理规则是否正确执行”，不验证自然语言抽取模型能否自动生成合理的初始置信度。

#### 专项配置

| 配置项 | 值 |
|---|---|
| 治理阈值 | `0.2` |
| 治理调用 | `force=true`，绕过一小时冷却时间 |
| 调度式治理 | 关闭 |
| 实验记忆 | 110 条，另有 1 条金丝雀记忆 |

#### 数据集与结果

| 分类 | 通过 / 总数 |
|---|---:|
| 明确淘汰 | 10 / 10 |
| 明确保留 | 10 / 10 |
| 信任等级对照 | 10 / 10 |
| 混合批次 | 10 / 10 |
| 安全与边界 | 10 / 10 |
| **总体** | **50 / 50（100%）** |

全部必需断言为 `597/597`。预期淘汰的 50 条记忆全部被淘汰，预期保留的 60 条全部保留；10 个重复治理 case 的第二次淘汰数均为 0，状态哈希保持不变。

#### 分析

结果说明当前有效置信度规则实际结合了初始置信度、记忆年龄和信任等级，而不是只读取一个静态分数。阈值两侧、信任等级对照、混合批次、重复治理幂等性和用户隔离均表现正确。

当前存储层的 `quarantine_low_confidence` 实际执行物理删除。API 字段虽然叫 `quarantined`，但系统没有可恢复的隔离区，因此只能表述为“低置信记忆治理或淘汰”，不能表述为“可恢复隔离”。本实验使用显式 `force=true`，不验证自动调度与冷却机制。

### 3.4 重复与近重复记忆处理

#### 测试内容

该实验验证：

- 完全相同或只有首尾空格差异的文本是否复用原记忆；
- 人类判断语义等价的不同表述是否被吸收或替换；
- 三个连续等价版本是否形成正确版本链；
- 同作用域独立事实是否安全并存；
- 相同文本在不同 user、branch、`subject_id` 和 `memory_type` 下是否隔离。

Memoria 的近重复查询先限定 user、branch、`memory_type` 和 `subject_id`，再检查 L2 距离是否不大于 `0.3162`。作用域 case 使用完全相同文本，L2 为 0，因而能证明并存来自结构性作用域隔离，而不是相似度不足。

该实验不验证事实值变化的通用自动更新；当前源码只承诺处理近乎相同的记忆。

#### 专项配置与数据集

| 配置项 | 值 |
|---|---|
| Case 数 | 50 |
| 写入数 | 104 |
| 近重复阈值 | L2 `0.3162`，约对应归一化向量余弦相似度 `0.95` |
| 精确重复 | 10 case |
| 语义等价 | 24 case |
| 并存与作用域隔离 | 16 case |

#### Memoria 结果

| 分类 | 通过 / 总数 | 通过率 |
|---|---:|---:|
| 精确重复复用 | 8 / 10 | 80% |
| 语义等价处理 | 12 / 24 | 50% |
| 并存与作用域隔离 | 16 / 16 | 100% |
| **总体** | **36 / 50** | **72%** |

阈值内的 16 个相邻等价关系全部正确替代；阈值外 12 个 case 全部并存。精确重复的两个失败来自同时包含首尾空格的文本：虽然 `trim()` 后完全相同，但 embedding 距离分别为 `0.3379645` 和 `0.4883051`，没有先通过 `0.3162` 的向量候选门禁。

#### 竞品对比结果

Mem0 Platform 和 Zep Cloud 与 Memoria 共同具有重复或等价事实处理链路，因此本项进行了正式竞品实验。三方原生可直接比较的核心集合为 44 case：10 个精确重复、24 个语义等价、8 个同作用域独立事实和 2 个 user 隔离 case。

| 核心可比范围 | Memoria | Mem0 Platform | Zep Cloud |
|---|---:|---:|---:|
| 精确重复 | 8 / 10 | 10 / 10 | 7 / 10 |
| 语义等价 | 12 / 24 | 24 / 24 | 15 / 24 |
| 独立事实与 user 隔离 | 10 / 10 | 10 / 10 | 8 / 10 |
| **原生可比合计** | **30 / 44（68.2%）** | **44 / 44（100%）** | **30 / 44（68.2%）** |

剩余 6 个 case 测试 Memoria 原生的 branch、`subject_id` 和 `memory_type` 去重隔离，Memoria 为 `6/6`：

- Mem0 的 `run_id`、`agent_id`、`app_id` 与上述三个 Memoria 字段语义不同。实验映射结果为 `0/6`，仅作为非同构适配观察，不计入 Mem0 主分数；
- Zep 没有同构字段，runner 通过拆分为独立 user graph 得到 `6/6`，这是适配结果，不代表 Zep 原生支持这三种作用域。

竞品运行版本如下：

| 产品 | 实验版本或 API 代际 | 正式运行 |
|---|---|---|
| Memoria | `0.4.0`；commit `54c9114fd6888e11821edc2ee9acd570c17c5ee3`；dirty source diff 已冻结 | `memoria-v040-54c911-dirty-qwen-v4-formal50-v1` |
| Mem0 Platform | API `v3` ADD-only；响应未返回服务端产品版本号 | `mem0-platform-v3-formal50-v1` |
| Zep Cloud | API `v2`；响应未返回服务端产品版本号 | `zep-cloud-formal50-v3` |

两个云服务只记录实际调用的 API 代际，不能把 `v3` 或 `v2` 当作产品发布版本，也不能把本次结果直接外推到未来服务版本。

#### 对比分析

- Memoria 的优势是行为可解释且作用域完整：branch、user、`subject_id`、`memory_type` 均是去重候选的结构性边界；局限是固定 embedding 阈值会漏掉明显等价改写，空白字符也可能影响候选门禁。
- Mem0 的语义去重覆盖最广，但 24 个语义等价 case 中只有 1 个最新写入改变最终状态。其 `24/24` 表示“没有形成重复活跃记忆”，通常是保留首条规范化表述并忽略后续等价输入，不等于完成了 24 次最新版本替换。
- Zep 通过 temporal graph edge、失效时间和 episode provenance 表达事实合并与演化，但抽取存在波动：部分 case 新增重复 edge，部分三版本链中新旧表述同时活跃，另有 2 个独立事实 case 出现旧事实被淘汰。

## 四、四项实验综合结论

| Feature | Memoria 正式结果 | 已验证优势 | 主要限制 |
|---|---:|---|---|
| 快照与回滚 | 50 / 50（100%） | 空间级恢复、跨级回滚、检索恢复和幂等性稳定 | 未覆盖并发、超大空间和生产容量 |
| 分支、差异与合并 | 48 / 50（96%） | 分支隔离、结构化 Diff、无冲突追加合并全部通过 | 基于记忆 ID 的冲突分类会误报语义等价变更；未测冲突解决 |
| 低置信记忆治理 | 50 / 50（100%） | 阈值、信任等级衰减、混合批次和幂等性全部正确 | `quarantined` 实际为物理删除；未测自动置信度生成和调度 |
| 重复与近重复处理 | 36 / 50（72%） | 阈值内替代稳定，独立事实与四种原生作用域全部安全 | 固定阈值和 embedding 对空格敏感，语义等价召回有限 |

四项结果不能直接平均后宣称 Memoria 的“综合准确率”，原因是每项实验的对象和断言数量不同。可以得到的产品级结论是：

1. Memoria 最具差异化且本轮表现最稳定的是空间级快照回滚、记忆分支状态机和基于显式置信状态的治理；
2. 分支冲突检测已经能覆盖真实分歧，但缺少语义等价归并，当前更接近版本 ID 冲突检测；
3. 重复记忆处理具有清晰的作用域和阈值规则，但对阈值外语义改写的覆盖弱于基于抽取或图谱推理的竞品；
4. 当前“治理”是确定性规则执行能力，不应扩大为自动判断记忆真实性，也不应将物理删除称为可恢复隔离；
5. 四项实验共同说明 Memoria 更偏向显式、可审计的记忆状态管理，但部分语义判断能力仍依赖固定规则而非更强的语义归并。

## 五、与 Mem0、Zep 的综合能力对比

下表比较的是本轮四项实验所定义的完整能力，而不是判断竞品是否存在任何相关概念。

| 能力 | Memoria | Mem0 Platform | Zep Cloud | 本轮是否正式横评 |
|---|---|---|---|---|
| 用户记忆空间快照与整体回滚 | 50/50（100%）；原生支持 | 未发现同构的整体快照与回滚接口；有单条记忆 history | 未发现同构的整体快照与回滚接口；有 temporal fact history | 否，竞品无同构操作链 |
| 记忆 Branch、Checkout、Diff、Merge 与冲突检测 | 48/50（96%）；原生支持 | 未发现同构链路；`run_id` 是运行作用域，不是可合并版本分支 | 未发现同构链路；user/group graph 是独立图，不是可合并版本分支 | 否，竞品无同构状态机 |
| 信任等级、年龄衰减与阈值治理 | 50/50（100%）；原生支持 | 有 Memory Decay，但只调整检索排序，不改变存储记忆 | 有 fact rating 与 `min_rating` 过滤，但不是时间衰减后的治理淘汰 | 否，相近机制的输入与状态结果不同 |
| 重复与语义等价事实处理 | 30/44（68.2%）；原生近重复阈值与版本替换 | 44/44（100%）；原生抽取与重复吸收 | 30/44（68.2%）；原生 temporal graph 合并、失效和新增 | 是；按 44 个原生可比 case 横评，另有 6 个 branch / subject / memory type 作用域 case 不适配竞品，不计入准确率 |

因此，不能简单表述为“前三项竞品完全没有”。准确说法是：

> Mem0 和 Zep 在历史、时间状态、评分或检索衰减方面存在相近机制，但没有提供与本轮前三项实验同构、可直接运行相同 case 的端到端能力，因此前三项只对 Memoria 做正式验证；第四项是三者共同具备明确处理链路的能力，因此完成了同数据集竞品对比。

竞品相近机制的判断依据包括：Mem0 官方的[单条记忆变更历史](https://docs.mem0.ai/api-reference/memory/history-memory)和[Memory Decay](https://docs.mem0.ai/platform/features/memory-decay)，以及 Zep 官方的[时间知识图谱与事实演化](https://help.getzep.com/v2/concepts)和[fact rating](https://help.getzep.com/v2/facts)。这些机制分别解决审计、检索排序、事实时间有效性或上下文过滤问题，不能替代本轮前三项所要求的整体回滚、可合并分支状态机或治理淘汰。

竞品相关判断以本次运行时可见的官方文档和 API 为边界。云服务会持续更新，未来若出现快照、分支或治理接口，需要重新冻结协议并复测，不能沿用本报告直接下结论。

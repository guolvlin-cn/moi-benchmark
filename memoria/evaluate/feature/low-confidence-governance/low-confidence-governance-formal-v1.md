# Memoria 低置信记忆治理能力正式实验报告 v1

> 实验日期：2026-08-13
> 正式结果：**50 个通过 / 0 个失败 / 0 个错误**
> 实验轨道：受控轨道（Controlled Track），直接写入明确的信任等级、初始置信度和观测时间

## 一、结论

本次正式实验验证 Memoria 能否根据记忆的信任等级、初始置信度和年龄计算有效置信度，并在执行治理时准确淘汰低于阈值的活动记忆，同时保护不应淘汰的记忆和其他用户的记忆状态。

在冻结的 50 个确定性用例中：

- 50/50 个用例通过，严格通过率为 100%；
- 597/597 条必需断言通过；
- 50/50 条预期淘汰记忆被正确删除；
- 60/60 条预期保留记忆保持存在且关键字段一致；
- 50/50 次金丝雀记忆检查通过，未发现跨用户污染；
- 10/10 个重复治理场景保持幂等；
- 无系统错误，也没有从正式分母中排除任何用例。

因此，本实验支持以下结论：

> 在本次冻结的受控协议与 50 个确定性用例中，Memoria 0.4.0 能够按照当前有效置信度规则准确淘汰低置信记忆，保留阈值以上记忆，并保持检索可见性、重复治理幂等性和用户隔离的一致。

该结论不等同于“Memoria 能自动为任意自然语言记忆生成正确的初始置信度”，也不代表当前实现提供可恢复的隔离区。

## 二、测试的能力是什么

低置信记忆治理以单条活动记忆为核心对象。Memoria 首先根据初始置信度、记忆年龄和信任等级对应的衰减周期，计算当前有效置信度：

```text
有效置信度 = initial_confidence × exp(-age_days / half_life_days)
```

当有效置信度严格小于 `0.2` 时，当前实现将直接从记忆表中删除该活动记忆；大于或等于 `0.2` 时予以保留。不同信任等级的默认衰减周期如下：

| 信任等级 | 当前代码含义 | 衰减周期 |
|---|---|---:|
| `T1` | Verified | 365 天 |
| `T2` | Curated | 180 天 |
| `T3` | Inferred | 60 天 |
| `T4` | Unverified | 30 天 |

实验将“治理正确”拆成五个可独立审计的层次：

| 层次 | 核心检查 |
|---|---|
| 治理计数 | `POST /v1/governance` 返回的 `quarantined` 是否与当前用户应淘汰数量一致 |
| 活动状态 | 治理后活动记忆集合是否精确等于预期保留集合 |
| 单条读取 | 应淘汰记忆是否返回 `null`，应保留记忆是否保持完整字段 |
| 检索可见性 | 保留记忆是否仍可检索，被淘汰记忆是否从检索中消失 |
| 安全不变量 | 重复治理是否幂等，其他用户的金丝雀记忆是否不受影响 |

## 三、数据集构造

### 3.1 基本原则

正式数据集为 `low-confidence-governance-formal-v1.jsonl`，采用“初始记忆 + 操作序列 + 程序化断言”的确定性结构。

数据构造遵循以下规则：

- 每个用例使用独立 `user_id`；
- 记忆正文使用正常自然语言，不加入人工检索锚点；
- 通过 `POST /v1/memories` 直接写入，显式声明 `trust_tier`、`initial_confidence` 和相对年龄；
- 全部用例共享一个冻结的 UTC 运行时间锚点；
- 数据集同时冻结 `expected_effective_confidence` 和 `expected_action`；
- 执行器在运行前重新计算预期值并校验 Schema、用例数量和分类分布；
- 每次运行保留原始请求、响应、状态、检索和逐条断言。

运行时将相对年龄换算为：

```text
observed_at = run_anchor_utc - age_days
```

本次运行锚点为 `2026-08-13T02:42:06Z`。

### 3.2 五类用例

| 分类 | 数量 | 覆盖内容 |
|---|---:|---|
| 明确淘汰 `clear_delete` | 10 | 单条明显低于阈值的记忆；其中 2 条低于检索层 `0.05` 下限 |
| 明确保留 `clear_retain` | 10 | 单条明显高于阈值的记忆，验证不被误删 |
| 信任等级对照 `tier_comparison` | 10 | 固定年龄和初始置信度，对比 T1/T4、T2/T4、T1/T3 和 T2/T3 |
| 混合批次 `mixed_batch` | 10 | 每个用户 5 条记忆，同时要求淘汰 2 条、保留 3 条 |
| 安全与边界 `safety_boundary` | 10 | 阈值两侧、同等级年龄边界、初始置信度边界、深度过期、多等级及重复治理 |
| **合计** | **50** | |

### 3.3 数据规模

50 个用例共包含 110 条实验记忆：

| 维度 | 分布 |
|---|---|
| 预期动作 | 淘汰 50 条，保留 60 条 |
| 信任等级 | T1 25 条，T2 23 条，T3 23 条，T4 39 条 |
| 记忆类型 | `semantic` 77 条，`profile` 33 条 |
| 数据集操作 | 497 个 |
| 预声明必需断言 | 597 条 |

共有 107 条记忆在治理前必须能被检索。3 条深度过期记忆的有效置信度低于检索层的 `0.05` 下限，因此它们在治理前只要求活动状态存在，不要求检索可见；治理后仍必须通过活动状态、单条读取和检索排除证明已被淘汰。

### 3.4 典型流程

```text
写入初始记忆
→ 捕获治理前活动状态
→ 验证应可检索记忆在治理前可见
→ POST /v1/governance，force=true
→ 捕获治理后活动状态
→ 逐条读取和检索验证
→ 检查金丝雀用户状态
```

安全与边界类用例会执行第二次治理，再次捕获状态并验证返回淘汰数为 0、前后状态哈希一致。

## 四、实验协议与判定方法

### 4.1 受控直接写入

本实验不经过对话记忆抽取模型，而是直接写入每条记忆的 `initial_confidence`、`trust_tier` 和 `observed_at`。这样可以将实验对象限定为“给定记忆状态后，治理规则是否执行正确”，避免将抽取模型的置信度预测误差混入治理结果。

### 4.2 状态与单条读取

治理前后都记录当前全部活动记忆及 `active_state_hash`。哈希纳入记忆 ID、用户、主体、内容、类型、信任等级、初始置信度、活动状态、会话、观测时间和额外元数据；`created_at` 和临时 `retrieval_score` 不进入哈希。

治理后：

- 被淘汰记忆的 `GET /v1/memories/{memory_id}` 必须返回 HTTP 200 且响应体为 `null`；
- 保留记忆必须在内容、类型、主体、会话、信任等级、观测时间和额外元数据上与写入值一致；
- 浮点置信度使用容差比较，不使用序列化字符串比较。

### 4.3 检索判定

检索使用 `/v1/memories/retrieve`，`top_k=20`。执行器允许最多 30 秒的检索可见性等待，轮询间隔为 0.5 秒。

本次共产生 217 条检索记录，全部在第一次查询时满足已声明的包含或排除条件，没有进入后续轮询。

### 4.4 金丝雀隔离

除 50 个用例用户外，执行器为独立用户 `feature-lcg-formal-canary` 写入一条高置信 T1 金丝雀记忆，并在实验开始时记录其状态哈希。每个用例完成后都重新计算该哈希；任何变化都会导致当前用例失败。

金丝雀记忆不属于任何用例，也不进入 50 条淘汰和 60 条保留记忆的统计。

### 4.5 用例状态

| 状态 | 定义 |
|---|---|
| `PASS` | 该用例全部必需断言通过 |
| `FAIL` | API 执行完成，但至少一条必需断言不通过 |
| `ERROR` | 用例因请求、协议或执行器错误未正常完成 |

`FAIL` 和 `ERROR` 均保留在正式分母中。

## 八、分类结果分析

### 8.1 明确淘汰与明确保留

10 个明确淘汰用例和 10 个明确保留用例全部通过。这证明在距离阈值较远的单条记忆场景中，治理计数、数据库活动状态、单条读取和检索结果完全一致。

对有效置信度低于检索层 `0.05` 下限的深度过期记忆，实验没有错误地要求其在治理前可检索，但仍通过状态和单条读取完成了淘汰验证。

### 8.2 信任等级对照

10 个对照用例在保持初始置信度和年龄相同的情况下，覆盖以下组合：

- T1 与 T4：3 个；
- T2 与 T4：3 个；
- T1 与 T3：2 个；
- T2 与 T3：2 个。

每个用例中，较高信任等级的记忆被正确保留，衰减更快的低信任等级记忆被正确淘汰。这说明当前治理结果不是只根据原始 `initial_confidence` 判断，而是实际结合了信任等级的衰减周期。

### 8.3 混合批次

10 个混合批次用例每个都包含 5 条记忆，预期在同一次治理中淘汰 2 条、保留 3 条。所有用例的治理计数、治理后精确集合和逐条读取均与预期一致。

这一结果证明在本次覆盖的小批量、单用户场景中，不同信任等级、年龄和初始置信度的记忆能在同一次治理中被正确分流。

### 8.4 安全与边界

10 个用例分别覆盖：

- 删除后重复治理；
- 无删除时重复治理；
- 深度过期记忆与正常记忆并存；
- 同一 T4 等级下的阈值两侧样本；
- 同一 T3 等级下的年龄边界；
- T2 和 T1 的年龄边界；
- 同一 T4 等级下的初始置信度边界；
- 多信任等级幂等性；
- 同时删除多条记忆的幂等性。

T1 年龄边界对的两个有效置信度为 `0.195368` 和 `0.206372`，分别被正确淘汰和保留；其他等级也构造了各自的阈值两侧样本。本次数据没有构造数学上恰好等于 `0.2` 的浮点样本，因此不对浮点精度极限下的严格等号边界作额外结论。

10 个重复治理用例的第二次淘汰数均为 0，治理前后状态哈希完全相同，幂等性断言全部通过。

## 九、实现语义与结果解释

### 9.1 `quarantined` 当前实际是物理删除

当前固定版本中，存储层的 `quarantine_low_confidence` 通过 SQL `DELETE FROM mem_memories` 删除满足条件的活动记忆。API 返回字段仍名为 `quarantined`，但数据库中没有对应的可恢复 `quarantined` 状态。

本次 50 条被淘汰记忆的单条读取均返回 HTTP 200 和 `null`，与该源码语义一致。因此报告使用“治理”或“淘汰”，不将结果表述为“可恢复隔离”。

### 9.2 `force=true` 的含义

治理 API 在 `force=false` 时会检查一小时冷却时间。本实验为了在每个用例中立即执行确定性治理，统一使用 `force=true`。因此本实验验证的是实际治理逻辑，不验证自动调度、冷却跳过或调度器重试。

## 十一、能力边界

本实验已覆盖低置信治理的核心确定性路径，但不验证：

- 对话抽取模型能否为自然语言记忆生成合理的初始置信度；
- 信任等级能否根据多条来源自动提升或降低；
- 跨会话自然语言矛盾识别与 `conflicts_with` 图标记；
- 来源部分失效或全部失效时的场景状态演化；
- 可恢复隔离区或被淘汰记忆的恢复流程；
- `force=false` 的冷却逻辑和自动调度器；
- 多用户并发治理、单用户超过 500 条待淘汰记忆的分批删除，以及长时间压力下的性能和稳定性；
- 浮点计算恰好等于 `0.2` 的极限边界。

此外，本实验不是与竞品的横向分数对比，而是对 Memoria 当前产品特性的直接能力验证。

> 在 50 个确定性用例组成的受控测试中，Memoria 0.4.0 对预期淘汰的 50 条低置信记忆和预期保留的 60 条记忆均做出正确处理，50/50 个用例、597/597 条必需断言通过。实验同时验证了阈值两侧、信任等级衰减差异、混合批次、重复治理幂等性和用户隔离。当前 `quarantined` 实现为物理删除，不是可恢复隔离。

## 十三、实验产物

不可覆盖的正式运行目录为：

`memoria/runs/features/low-confidence-governance/memoria-v040-54c911-qwen-v4-formal50-v1/`

目录中包含：

- `manifest.json`：版本、模型、数据集哈希、运行锚点和协议配置；
- `initial-state.json` 与 `final-state.json`：实验前后数据库统计；
- `cases.jsonl`：实际执行的冻结用例快照；
- `operations.jsonl`：全部原始 API 请求与响应；
- `states.jsonl`：治理前后活动记忆状态及哈希；
- `retrieval.jsonl`：检索请求、返回别名和原始结果；
- `assertions.jsonl`：597 条逐项断言；
- `case-results.jsonl`：50 个用例的状态与计数；
- `canary.json`：金丝雀用户及基线状态哈希；
- `metrics.json`：总体和分类汇总指标。
